# 提前抢收（0.3.41）

晚播的田可能赶不上入冬前成熟，缺粮时也可能等不起完整秋收。农田原面板新增“提前抢收”：看清本季产量损失后确认，换取更早开始收割的机会。

## 玩家规则

- 全田播完、至少长出基础每格1单位、尚未收完且非冬季，才可下令。已成熟的秋田继续正常自动收获，不必再点；成熟的夏田也可手动开始。
- 确认时锁定基础每格产量为 floor(14 × 当前成长比例)。例如50%成长锁定7/格；确认后该田本季停止继续成长，不可撤销，也不能同年再次播种。下一春恢复正常播种，仍沿用已选的下季作物。
- 农夫实际到田、逐格工作、攒筐搬到可达仓库，入库后粮食才供居民使用。按钮不发粮、不加人、不改工具效率。三类食物保持：小麦产主食，卷心菜产蔬菜。
- 面板列出当前工具条件下的每格、剩余田块估算、等待全熟估算及差额。确认期间日期、成熟度、作物或工具条件改变会要求重新确认。估算不是保证入库：缺工、路不通、工具用尽、仓满或未抢在入冬前割完都可能降低实际到仓数量。
- 抢收田按可收获粮岗参与保粮与调度，避免夏季仍被当作纯等待生长的空闲岗位抽走。只针对该田，其他夏田保持原规则；用工上限仍有效，设0后结清当前任务/货批才撤岗。优先施工不额外夺走保底粮工。
- 正常春夏播种、成长24天、成熟后秋收和冬季损失规则保持。没有新灾害，没有改农田大小、成长速度或满熟产量。

## 存档与中断

每田只新增可选整数 earlyHarvestYield。不存在该字段的旧档继续原自动秋收；新字段必须与已播完的实际田块和成长比例一致，非法类型、越界或挂在非农田上会在替换世界前拒绝。

实际已割作物只产出一次，已背起货物保留种类和数量。冬季清掉未割作物与旧任务，春季清掉本季抢收计划；读取存档不重新收获、不额外成熟。完整路线/未完成小段仍沿用现有读档重建合同。

普通粮食满仓溢出规则未重构；面板明确提示仓满风险，经营流水区分生产、入库与弃货。本片不声称解决所有普通粮食满仓余量保全。

## 依据与适配

[Banished Wiki: Farming](https://banished-wiki.com/wiki/Farming) 描述可命令农夫尽早收割以抢救已经长成的作物。本片只实现主动抢收选择，不加入虫害。固定8×8、14/格及按全田成长比例锁定单格整数产量均为本作适配，不是原版逐株温度模型的精确复刻。

复用现有小麦/卷心菜生长美术与收割后的田块状态，没有新增素材。

## 定向证据

- node tests/early-harvest.js：真实收割/搬运与三类库存、日历+载入、冬春旧任务、工具、缺工/用工0、断路复通和确认时无瞬时收益。
- node tests/early-harvest-ui.js：两步确认/取消、变化报价、旧世界/面板回调、模态框中断、原按钮与焦点保持；属于DOM检查。
- 在固定布局的晚秋第33天，50%成长田进行实际日历对照：默认等待至入冬产出0；抢收在入冬前实际割出336，低于448在田潜力，因为时间和运输仍真实消耗。这是单场景证据，不是所有布局承诺。
- 关联检查覆盖原种子/农田、经营流水、用工、存档与基础启动。原种子测试的直接跳至秋季fixture同步重置账本起日；其旧“流水日期缺失”在精确base复现，不降低导入验证或移除断言。

没有真实浏览器/手机验收或生产部署。既有两项无关施工几何基线失败不在本片宣称修复。
