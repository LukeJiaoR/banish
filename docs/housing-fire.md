# 水井与可选住房火灾（0.3.55）

这片增加“提前准备水源和临时住房 → 烟警撤离 → 空闲成年人真实提水 → 扑灭或烧毁 → 原址重建”的小闭环。仅木屋、石屋参与，不是原版全部灾害系统。

## 主动开关与风险节奏

- 新游戏、旧档都默认关闭，在已有市政厅详情内查看规则并二次确认开启。首次开启有完整48日宽限；关掉后再开不会重置首次启用日或再送一轮宽限。
- 宽限结束后，全镇每日进行一次1.5%起火尝试；只会选已完工且有住户的木屋/石屋作为起点。石屋被选中后再过50%判定。已有事件期间不产生第二个独立事件，两次独立起火至少间隔24日。
- 起警立即撤离，前12小时只有烟警、没有结构损失；之后按36小时燃烧窗发展；没有浇水延缓时，从烟警开始共48小时后烧毁。每场火需要实际浇3桶水，每桶还把火势时钟往回推6小时，争取后续救援时间。
- 着火后每6小时检查一次近邻。仅占地间隔不超过2格的木/石独栋可能传播，木屋15%、石屋7.5%，包括空屋；整个事件最多涉及3幢房屋，已涉及的房屋不会在同一事件中再次起火。烟警阶段不传播。
- 关闭也需要确认：仅阻止未来独立起火和新的邻屋传播，现有烟警、燃烧、损伤和取水救援继续。关闭不会灭火或修复房屋。

以上概率、宽限、时间、传播上限和“仅住房”都是本作可试玩适配值。火灾本身不直接杀死居民；迁出造成的露宿仍受原有冬季寒冷和饥饿规则影响，不能把“无直接火灾死亡”理解为无生存风险。

## 救援人力和真实水路

- 城镇服务新增2×2水井：16木24石、60基础建造工时，无常驻岗位。水不是新的公共资源，不能交易，也不消耗粮柴或矿物。井的位置和道路决定实际往返成本。
- 每个事件最多2名救援者，只从18岁以上、健康、未饥饿/严重受冻且真正空闲的成人中选。必须无岗位、无任务/挂起批次、无已有携货，且不是学生或刚入村者。
- 不抽走教师、医师、农夫或其他在岗人员，不抛弃任何生产批次。缺人时警报与市政厅直说缺少空闲散工；玩家可降低非关键岗位上限，等该批工作与送货结束后释放人手。
- 救援者先按现有道路加权寻路前往可达的完工水井或河湖岸边，实际取水半小时，携水返回火点入口，再实际浇水半小时。石路、冬季速度和提水减速正常生效，格内最后一小段也要走完，不传送。
- 救援可跨夜继续，仍承受正常户外寒冷。已占救援的人不能被普通派工又分配一次。无水路/回程封路会保留当前任务（已取水则保留这一桶），按2小时间隔重寻，详情说明等待原因；火点结束后释放救援者。
- 临时水桶只属于救援任务，不写进 `c.carry`，不会覆盖木、矿、衣服或食物等已有实货。

## 撤离、返住与重建

烟警开始立即腾空原家庭，沿现有安置规则进入空独栋或宿舍；没有空床则暂时无房。家庭、配偶、儿童、教育及随身货物都保留。旧回家/睡眠路线失效，住户不能继续把着火房当成暖屋，着火房不取暖或生育。

扑灭后房屋重新成为可入住空房，只按当前家庭与空床重新分配。已经住进另一独栋的家庭不会被强迫搬回，也不会挤掉当前住户。任何火情中的房屋都不能通过拆除或升级直接消掉火灾。

未救下的房屋变为同位置废墟：仍占地，不能居住。可以零退款清理，或在详情查看原房型、全额新材料和冬季临时安置风险后，二次确认原址重建。重建只扣一次新材料，使用原有真实施工、暂停、优先级和完工安置。取消按当前工地规则退还新投入，绝不返还早已烧毁的旧材料；同一废墟重复确认、另一次火灾留下的旧确认、切村/同ID读档后的旧控件均不能重扣。

## 保存与显示

保存开关、首次开启日、宽限、日界检查、事件序号/已涉及房屋、各火点进度/剩余桶数/下次传播点，以及废墟来源。载入不补算过去随机起火，不重放已浇过的水，不刷新传播上限。错误火情、入住关系、废墟退款或事件序号在替换活动村庄前拒绝。

沿用原有“未保存任务/路径”的合同：读档会取消未完成的救援路程，临时水桶不保存，居民会重新到真实水源取水；只有已经实际浇到火点的灭火进度被保存。公共库存、原携货和房屋损伤不会因任务重建而复制/丢失。换季自动档仍可能处于本次日界事件前，不宣称精确逐步重放。

新增水井和废墟为按完整原提示词、既有木屋/石屋/矿坑参考生成的原创透明PNG，各320×256、50%显示、底角居中。水井与木屋均占2×2格，井体可见宽约123像素，对齐128像素地格；160像素画布含透明边距。烟警/火焰/提水小桶为少量代码绘制效果，详情有对应文字，不只靠颜色。现有居民动作素材复用，未声称新增完整提水动画。

## 原版依据

- [Well](https://banished-wiki.com/wiki/Well)：提供居民灭火用水。
- [Fire](https://banished-wiki.com/wiki/Fire)：井与河湖取水、附近建筑传播、材料和间距影响风险。该页对具体传播距离使用玩家报告，本作没有把传闻距离当精确原值。
- [Disasters](https://banished-wiki.com/wiki/Disasters)：灾害可开关。这里仅新增住房火灾，虫害仍用已有独立设置；未加入龙卷风、矿难或全建筑/森林火灾。

## 已有定向证据

- `node tests/housing-fire.js`：17组核心，包括实际近井/远河、封路复通、真实冬季迁宿舍→烧毁→付新料重建→暂停/读档→完工返住、旧档默认关、宽限/传播/关闭、货物和岗位保护、坏档拒绝、普通/受教多人实际施工留下负余工时后烧毁与重建两轮读档。
- `node tests/housing-fire-ui.js`：32组DOM/实际API，开关与重建确认、状态/焦点保留、报价/世界/节点/弹窗/同ID真实载入守卫，现有市政厅迁入决策仍可用。
- `node tests/housing-fire-render.js`：原创PNG格式尺寸与半尺寸锚点、烟警/火焰区别、救援携水不挥斧。
- 同房屋与两成人的平坦布局，近井用5.6游戏小时扑灭，远河在第55列，两人确实走到54列并提水，却在48小时内无法返回，房屋烧毁。前者体现短水路收益，后者证明真实运输成本，不用“低概率未遇事件”冒充验证。
- 默认关闭，正常seed1真实3年仍20人口、0死亡、基础6/6；住房升级、用工、教育、矿产、存档、基础启动做定向回归。
- 顺手修正上一片旧无限矿点在人资面板覆盖仓满原因的文字优先级，仅有限矿点优先显示储量不足；不改变矿点产出或仓容。

离线Canvas与DOM不等于浏览器/手机试玩，无部署。既有 building-completion 两项旧几何夹具与 resource-goals-recovery 旧seed29断言不在本片宣称的全通过范围。
