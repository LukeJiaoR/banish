# 建筑详情分层导航

仅重排建筑详情，不改变产量、经济参数、保存数据或确认条件。

- 默认打开概览；运行状态、当前活动和低矿藏预警位于栏目上方。
- 概览用紧凑字段显示位置、阶段、实际用工，并提供用工/施工和管理入口；建筑说明按需展开。
- 按实际内容显示生产与工人、库存与运输、管理。工地称施工与工人，贸易站称贸易与工人，教学/礼拜/医疗称服务与工人；住宅无虚构生产栏目。
- 生产链库存、投入和在途批次，伐木屋燃料库存/供暖缺口，住宅补给、市场配送、堆料场与工地建材分别进入库存与运输。普通仓库明确显示全镇公共库存，不假称逐仓现货。
- 贸易、牧场、农田、果园与市政厅内再用二级菜单组织操作与规则；交易报价、确认后果和相应操作保留在同一功能菜单。
- 升级、退款、拆除及其确认归入管理；地图拆矿、拆墓园、拆隧道会主动打开管理中的原确认。

## 状态与输入

栏目按钮支持 Tab、左右方向键、Home/End，使用 aria-controls / aria-pressed；隐藏栏目同时使用 hidden 类和 inert，不能通过正常键盘导航进入。切换建筑/世界回到概览，原来位于旧控件上的焦点回到安全关闭按钮。

同一建筑的实时刷新保持栏目、输入草稿和焦点。需要整体重建时保留滚动及已展开的功能菜单；不把新商船的旧交易意图带入新订单。离开栏目清除该栏目升级、拆除、供给规则、虫害、抢收、分群、搬空及自动交易的待确认状态，未应用的普通输入草稿保留。所有旧模拟 API 与控制上下文检查继续使用。

## 验证入口和限制

- `node tests/building-detail-navigation-ui.js`：真实模拟 API + DOM fixture，覆盖建筑类型、键盘、刷新/重建、新选择、过期菜单、用工更新、库存语义、离栏取消确认及二级分组。
- 既有 `tests/*ui*.js` 与 `tests/ui_economy.js` 用于确认与控件回归；具体结果记录在交付报告，不能把历史失败称为通过。
- VM 普通 Chromium 启动被 `socket() failed: Operation not permitted` 阻止，未绕过限制。没有真实浏览器、手机截图或视觉/触摸验收通过的声明。CSS 提供窄屏宽度、可滚动面板及较大触摸菜单目标，但仍须真实浏览器验收。

与未发布的启动矿产修复共享 `js/ui.js` 文件。该修复只修改矿藏说明，导航改动独立于地形/矿产逻辑；集成时须精确合并对应说明并重新运行 DOM 检查，不覆盖整份 UI 文件。
