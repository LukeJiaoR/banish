# 耐寒瓜与入冬两日收获窗口（0.3.72）

任务 [#81](https://github.com/LukeJiaoR/banish/issues/81)，基于 0.3.71 / `2d94fd4912bcff3238af50b47b95e33af988aa00`。本片增加一个有收成时序差异的作物，不代表全部原版农业或气候已完成。

## 原版依据与适配

[Farming](https://banished-wiki.com/wiki/Farming) 把 Squash 列为独立作物，说明它能耐受约 −2°C；[Squash](https://banished-wiki.com/wiki/Squash) 说明农田、种子与虫害关系；[Seeds](https://banished-wiki.com/wiki/Seeds) 支持正常价值 2500、一份永久解锁、重复购买无益。Squash 和原版 Pumpkin 是两个条目，本片称“耐寒瓜”，不把它们当同一个新物品。

本作没有气温模拟。Wiki 的冬季概述与耐寒细节并列，本片采用明确的日历适配：一年 48 日、每季 12 日，入冬后的前两日仍保留已种耐寒瓜，第 3 日零时清除未采下的作物。第一年对应内部 `day=36,37` 可收、`day=38` 截止；往后每年同样计算，不是每次读档再给两天。

24 日生长、每格基础 14 蔬菜沿现有卷心菜量级，是本作适配，不声称原版精确产量。冬季绝不播种、补播或增长成熟度。成熟作物继续逐格收割；全田播完但尚未成熟的作物，可在窗口内用既有二阶段确认抢收，按当时成熟度锁定减产量。等待冬季不会增产。田太大、农夫不足、远路、夜间休息或满仓依然可能错过截止。

## 玩家可见的流程

1. 种子商提供“耐寒瓜种子”，正常价值 2500。原有同商人订单、溢价与到港自动购买规则通用。成交支付实际贸易库存；一份永久解锁所有农田，不占仓位，不能反复付费买同一种。
2. 农田“下季 / 空田选择”新增耐寒瓜。春夏尚未开种的空田可以立即选；已接受首播任务、已播种、生长、已收获的田仍锁定本季实际作物。晚改选不会让小麦突然耐寒，也不改已背起的粮。
3. 入冬后，详情显示冻结成熟度、当前工作状态、精确剩余小时、不能冬播或等待增产，以及第 3 日截止。成熟田正常收割，未成熟全播田可确认抢收。过时的报价、关闭 / 换田后的旧控件不能继续操作。
4. 第 3 日未采下的格子归零并提示格数；已收库存和在途货不受霜期清田影响。春季仍统一复位，每年只种收一季。

## 实物与旧存档合同

- 作物逐格完成收割才产出，攒筐与走路送仓沿原链。耐寒瓜进入现有 `vegetables` 实物库存，不新增第四营养组。仍是肉类、蔬菜、主食三组，名称不重定义。
- 截止清田使当季未完成及夜间暂停的播种 / 收获任务失效，不清携货、不补产“理论收成”。改种、改岗、拆田、读档沿已有所有权合同；旧田不会被替换成耐寒瓜。
- 现普通农田携货满仓时，多余部分仍按原规则记入市政流水“丢弃”，不在本片暗改仓容或建立独立仓库存量。死亡后尚未由专属货物处理器回收的食物，维持原损失结果，但补记同一流水损失且仅一次，避免死亡损失无记录；狩猎 / 家庭补给的既有处理先执行。
- 旧存档没有 `unlocks.squash` 时按 `false` 读取，不赠种子、田粮或额外贸易货。原小麦 / 卷心菜 / 豆类的种收规则不变，旧菜库存不改名。
- 新田已播状态、实际作物、下一季选择、成熟度、抢收锁定、已收格与携货保存。截止后伪造的未收耐寒瓜田拒绝导入；完整读取检查在替换当前村庄前完成。已收完田与有效携货可正常保存。
- 0.3.71 的建材实运状态、已付旧工地、在途材料及进度保持原合同。

## 美术和验证口径

仅新增耐寒瓜四阶段，沿原提示词、2:1 视角、左上光、透明背景和田格比例；接入现有动态作物前缀，其他作物与人物不重画。素材过程见 [美术说明](art-assets/squash.md)。

针对性检查覆盖种子交易 / 订单 / 自动买、入冬冻结与截止、抢收确认和旧控件、真实携货与损失、旧档及新状态往返、原作物、建材和受影响 UI。离线 Canvas 与 DOM 模拟不是浏览器或手机实测，远端检查状态以 PR 对应提交的实际返回为准。具体结果在 PR 与 Issue 验收回执记录。
