# 0.3.5 采运与冬季复核

完整紧凑结果见 [本轮与留出种子](winter-feedback-results.json) 和 [seed41四臂因果对照](winter-recovery-results.json)。

基线：main `a6700f6acad0ae93ee9e27724c6435e285ecdda8`（0.3.4）。本轮不改变资源产量、消耗、工具磨损、生育或受冻参数。

## 修复与操作反馈

- 不可达的砍伐/采矿标记不再占用预留散工。原版可在河对岸画三个标记，使唯一成人保持无业、可工作的食物岗位反而无人。现在按成年市民所在连通区域判断；标记保留，后续地形或市民位置变化会重新检查。使用与现有寻路同样的阻塞终点替代规则，四向连通与禁穿角八向寻路一致。“可达”只表示至少一个活成人能走到，不保证该成人可立即从教师/保粮等岗位抽出；跨岛劳工分配仍是全局调度的已知局限。
- 砍伐/清矿工具显示待领、执行（含赶路）、跨夜保留、散工人数及最近派工时的不可达检查。检查是历史快照，标注时间，不把它伪装成实时路径诊断。
- 资源提示将仓内库存与市民随身资源分开。原木为零但已有待砍/在途物资时，提示查看进度或等待送仓，不再无条件催玩家继续扩大队列。
- 标记时在地图保留现有采集/狩猎小屋的方形食物林边界，降低误砍食物林的试错成本。帮助修正为真实实现的“点击或拖拽沿线标记”，没有矩形框选。
- 退出工具不会撤销已画标记，面板明确说明。目前仍没有取消标记入口；它是已知操作局限，本轮没有以清空集合冒充完整取消（已认领/跨夜任务也需要处理）。

## seed41：策略瓶颈、自动派工与正常操作救援

原冻结长期策略要求住房/护林前有超过12天粮食。只有500容量的仓库、25人口时最多只能存约9.6天粮，这个脚本门槛已无法达到；另一个高木材扩仓门槛又与持续补柴争用原木。工具短缺包括脚本主动将铁匠上限设为0以保留矿井铁料，并非所有短缺都能归为产量不足。

派工也存在路径依赖：低粮时，15成人可全在食物岗位，空着的伐木岗位无法从保护线内抽人；若原本已有一名伐木工，则会受保护。尝试过“缺全年柴就强制让出食物工人”的候选，救了41却令原本正常的seed5出现6饥饿人日、末粮仅1.3，因此没有提交这项改动。不能用一个种子的全绿掩盖别处的饥荒。

精确0.3.4基线上，一组可在现有UI执行的因果对照是：d192暂把燃料目标降到0，攒到48木16石后d231下第二仓库，再恢复原目标150，其余冻结长期规则不变。30年末36人、21出生，其中3次由本局出生者生育；0死亡、0饥饿人日、0无工具日，仍有24冷屋日。原策略同种子为7次冻死、3无工具日、没有本局出生者再生育。降低燃料目标会增加缺柴风险，不能作为无条件通关指南；对照证明这个地图可由真实资源分配操作恢复，不证明任意时机停柴安全。

## seed44：已有因果证据保留

0.3.4记录的同规则对照仍适用：26格内非食物林耗尽后向外找可达树，能避免后续断柴灾难，但首冬同一名无房儿童仍冻死。没有重新标成零死亡，也没有用本轮信息面板宣称它自动改变玩家决策。
