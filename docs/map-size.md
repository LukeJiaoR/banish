# 新局可选 192×192 地图

地图尺寸功能已通过 PR99 合并。对应用户 2026-10-10「地图不够大，资源不够丰富，继续吧」的扩图目标；独立于 #87 / Draft #98 美术候选。美术候选仍未采用。

## 范围与取舍

- 原 128×128 仍默认。新局设置可选 192×192，原地形／山地和经典／困难预设均可组合。192 是本作适配尺寸，不称原版中型尺寸。
- 192 边长是原来的 1.5 倍，土地面积 2.25 倍；沿用噪声尺度、矿石与森林生成密度，不复制区块、不赠库存或免费建筑。更多总土地不保证每个种子每项资源精确增至 2.25 倍，也不保证近处资源更密或任意经营策略生存。
- 现有村庄不会扩大。选择尺寸只修改草稿；更改尺寸使已检查的确认过期，必须重新检查、再确认。取消、失焦旧点击、生成失败均保全原村、随机流和存档。
- 初始人数、食物、材料、种子、衣物和工具规则不变。山地沿用实际起始车占地后的住宅/工坊用地、有限木石铁、水岸和食物林可达性证明；后续经典新村的近镇石铁保障与地形版本见[近镇石铁规则](starter-minerals.md)，历史村庄保持原地形。
- 地图尺寸属于每个 world.N，不修改全局默认 G.MAP。寻路、采运、道路、建筑与镜头沿现有世界尺寸工作。隧道原有最长128格的玩法边界不随地图扩张。
- 无新素材、气候、逐仓库存、CI、付费调用或生产部署。

## 保存合同

下文记录 PR99 的历史 v1/v2/v3 合同；当前新经典村改用 v4，完整规则见[近镇石铁规则](starter-minerals.md)。旧三类存档仍按下述方式读取。

128 经典／山地保留原根 v1／v2 与开局配置形状。192 新局写根 v3，并强制记录开局配置 v3（preset、seed、terrain、mapSize:192）及完整 water/rock/mountain/start 地形。地形算法版本仍按经典1／山地2区分。

读取 v3 按其权威尺寸分配，再恢复实际地形、道路、已采矿点、树木、建筑、人物和货物；不重新生成、不补启动矿或库存、不裁掉128之外的实体。尺寸／配置／地形种类不一致、缺失字段与非法地形原子拒绝。旧程序拒绝未知根 v3，避免把192村庄静默加载成128。读取旧档不重新给尺寸设置、不改旧地形。

任务和随机数位置仍遵守原存档的重排约定，不承诺逐帧任务回放。既有默认字段在首次载入时可能规范化，此为原合同；测试区分首次规范化与后续幂等。

## 预算与验收

地面缓存继续现有 16,000,000 像素上限。它只限制一张地面 backing surface（RGBA约61MiB），不等于整个浏览器/GPU内存上限；192冷绘制访问更多地格，可能更慢。没有增加新的地面缓存、分块渲染框架或手机性能承诺，设置页明确提示手机性能未实测。

针对性入口：
- `BANISH_BASELINE_ROOT=<未修改的v0.3.79源码目录> node tests/map-size.js`
- `node tests/start-settings-ui.js`
- `node tests/ground-cache-budget.js`
- `node tests/mountain-start.js`

覆盖两地形×两预设×8种子共32组：实际生成可重复、库存／家庭数、实际连通图中的木石铁与水岸、山地既有开局证明、序列化体积；另覆盖尺寸恢复、远端实体／道路／已采矿点、实际绕障沿路携货及读档续送、非法档原子拒绝、128旧引擎等价和旧引擎拒绝v3。新局DOM增加尺寸草稿、失效确认、返回修改和两次开局验证。

以上是本地模拟、真实生产接口及DOM检查，不是浏览器／手机视觉验收，不代表完整生存策略矩阵。具体运行结果以冻结证据为准，独立审查尚待执行；不以“原有测试失败”掩盖新回归。
