# 可玩性与经济回归

## 如何复测

```sh
# 正常开局、历史开局脚本与三组负面对照：8 个固定种子，各 5 年
node tests/playability.js --assert --json /tmp/playability.json

# 与修改前版本运行同一个测试文件和同一个策略，不能用旧版 opening.js 代替
node tests/playability.js --root /path/to/cdb7a7c-checkout --strategies normal,original --json /tmp/baseline.json

# 单变量食物产能实验：引擎和策略不变，仅替换每次采集的满产基数
node tests/playability.js --strategies normal --gatherer-yield 5 --json /tmp/food5.json
node tests/playability.js --strategies normal --gatherer-yield 6 --json /tmp/food6.json
node tests/playability.js --strategies normal --gatherer-yield 7 --json /tmp/food7.json

# 第一冬燃料库存目标的单变量实验
node tests/playability.js --strategies normal,fuel200 --years 1 --json /tmp/fuel.json

# 通用远矿补救与未用于制定策略的新种子
node tests/playability.js --strategies adaptive-mining --seeds 23 --assert
node tests/playability.js --strategies normal,adaptive-mining --seeds 33,34,35,36,37,38,39,40 --assert
```

可用参数：`--root`、`--seeds 1,2,3`、`--years 5`、`--strategies normal,original,neglect,no-fuel,overexpand,fuel200,adaptive-mining`、`--gatherer-yield`、`--json`、`--assert`。默认打印结果而不因验收失败退出；持续集成应带 `--assert`。失败会逐项列出，不能把一次有输出的运行写成“通过”。

## 测试约束

- 固定种子 1–8，不筛掉地形差、缺矿或失利的地图。每年 48 天，步长 0.5 游戏小时，运行 5 年；人口归零即结束。
- 使用真正的 `G.newGame`、资源成本、建筑工时、寻路、运输、进食、工具磨损、冬季受冻、生育和自动职业调度。
- 除游戏本来的初始储物车外，策略不使用免费或瞬间建造，不修改资源、人口、饥饿、寒冷、工作速度或工人职业。燃料上限、建造、标记采伐/矿石均是玩家已有操作。
- 仅省略画面、声音和自动保存的网络调用。每个案例使用独立 VM；一轮运行开始后缓存所有引擎源码，避免编辑中的代码混入后续种子。JSON 包含源码及策略 SHA-256 和显式实验参数。
- 两版比较的是同一套决策规则；资源变化可能导致建造日期和随机流分岔，不能声称是完全相同的行动序列。地图修复也可能改变同一种子的出生点，组件级因果判断另用定向回归及单变量实验。
- 这是有地图信息、会安排建设的脚本玩家，不代表完全不看提示的新手；五年稳定也不等于二十年、极端人口或所有种子都已验证。

## 两种正常/历史策略

`original` 是 cdb7a7c 的 `tests/opening.js` 建设策略冻结副本，保留原来的半小时决策频率及错误，便于追溯，不把它改成更聪明后再称为原版对照。

`normal` 每半天决策一次：

1. 按实际工作圈而非外观中心选采集屋，扣掉建筑脚印会清除的树，要求至少十棵余树，偏好成熟森林；仓库旁建伐木屋，再建第二座采集屋。
2. 先建三栋木屋保护最初带儿童的三个家庭，其余家庭后续按资源扩建；一次只保留一个工地。
3. 小批量标记木材/石头/铁矿，避免树队列永久压住矿石；不砍采集屋工作圈内的食物森林，其他建筑也优先避开这些树。
4. 燃料目标至少 100，按已入住住房的实际年需求向上取整到 50；秋冬燃料不足时暂停非必要扩张。
5. 工具低于 10 时补一座铁匠铺，提前收集铁。只建一座，按真实 42 木成本判断，不因额外木料缓冲而错过工具耗尽前的窗口。
6. 第二年春在食物能支撑施工时建一块农田；优先选少砍树的空地，避免农田清场破坏食物森林。粮食不足八天时补第三个采集点。
7. 工人和粮食足够才增加护林屋，放在食物林的另一侧；食物接近仓储上限且资源足够时增仓。住房最多五栋。

这些改动修正的是脚本的决策错误，不应算作引擎带来的收益。最终前后版本必须都重新运行同一份 `normal` 策略。

## 不放宽的验收线

每个 `normal` 案例：

- 活到所要求的年限，五年末人口至少 15
- 第一冬结束前没有死亡，整个测试没有饿死
- 五年内冻死最多两人（目标仍为零；阈值为地图与人口波动留小幅余量）
- 结束时至少三天食物，仍有工具，工具完全耗尽累计不超过两天

负面对照：

- `neglect` 完全不建设，初始 500 食物仍应在 24 天内耗尽并使原始 15 人饿死
- `no-fuel` 采用正常策略但不建伐木屋，两年以后应确实出现冻死
- `overexpand` 第二年起只要够钱就抢先加住房，不留燃料/工具/食物建设余量；多数配对种子的死亡应多于正常策略

不能靠关闭饥饿/寒冷、送库存、假造工人或把负面对照也变成安全开局来通过。

## 指标说明

JSON 记录死亡时间、死因、死亡时库存/住房、出生与最终人口，各资源末库存和全程最低库存、分冬季最低粮/柴、每季快照、建设顺序、工具耗尽天数、饥饿人日、未供暖房屋日、各岗位累计工作人数×小时、任职次数与任务中断次数。

`production` 是任务完成时真正增加的背包与库存数量，按建筑类别/资源分组；包括散工木材和矿石，不包括初始化库存或建造时清场返木。即时入库被仓储上限截断的部分不计入，因此它是实际完成收益而非理想满产。岗位小时包括被任职但休息/等料的时间，适合查“挂着岗位却没有产出”，不能直接当纯劳动工时。

## 已确认的原始问题

- **种子 1 的假好成绩：** 初始固定位置的储物车可能因岩石占地建造失败，却未被检查。没有仓库时生产走即时入库兜底，免去了真实运输，单种子开局因此高估经济。
- **铁矿软锁：** 原始种子 2 全图没有铁矿，种子 3 最近铁矿约 145 格远；开局无铁而矿井又需要 10 铁，工具循环存在不可恢复的地图锁。新图保底是可达的地表矿，仍须真实劳动开采，不是直接送库存。
- **过量工具吞木：** 原始 seed1 五年历史策略留下 266 工具而发生四次冻死；无限制铁匠产出和缺少重复建造判断都不应被当作必然生存难度。
- **调度而非基础数值：** 全局粮食劳动力被错误地按单栋判断；保留的散工又被当成“已有空闲工人”而阻止重新平衡；无料岗位的释放标志过早清掉；已收完的农田仍可抢伐木工。实际现象包括有木材、有加工建筑却长期没有柴火产出。
- **原脚本决策错误：** 石头未到 120 就不标树、不专门找铁、铁匠没有数量判断、近处食物林被持续砍薄、低粮时仍无条件扩张。它的失败不能全部归因于引擎。

### 采集基数单变量实验

早期冻结实验的引擎摘要为 `747947620608be6a9de785e7a2ef4461c422e9873eca19cf150e86abc1759376`，使用最终正常策略，仅替换采集每次满产基数。5 为 44/48（种子 1 饿死 22、种子 5 冻死 10），6 和 7 均为 48/48、八个种子零死亡。当时采用较小的 **5→6** 调整，没有降低食物消耗、寒冷或工具磨损。后续无料岗位调度修复后，5 也已通过；不能把最终收益全部归因于采集增产，同参数复测见下。末次单变量实验固定引擎摘要 `eeb6edcde552fdd839ba932bf2fbd274f1944169ba57b9b1a3bc372bf49142fb`，只覆盖采集基数。

- 最终引擎基数 5：48/48，8/8 五年零死亡，总死亡 0。
- 最终引擎基数 7：48/48，8/8 五年零死亡，总死亡 0。
- 最终引擎基数 6：48/48，8/8 五年零死亡，零饥饿人日、零工具断供。

最终三档都能通过，因此**撤回 20% 采集增产，保留原基数 5**，以原产能的调度修复作为最终方案。以上主矩阵及后续验证已按默认 5 全部重跑；不能把改善归因于多发粮食。负面对照仍验证了粮食、取暖和无节制扩张的真实代价。

单变量实验固定的是规则而非建造日期：收入会改变决策时间和生育随机流，不能假定每个种子的结局随基数严格单调。

### 最终燃料上限隔离实验

同一最终引擎和策略，只把最低燃料目标从 100 改为 200：

- 100：八个种子首冬零死亡，冬末柴火 64.5–86。
- 200：八个种子累计冻死 12 人，冬末仍存柴火 148.5–205.5。

默认提前囤过多燃料会抢占前期住房所需原木；100 是较温和的起点，住房需求增加仍需提高燃料上限。这不意味着任意规模的村庄都适合固定 100。

### 通用补救验证：自适应找矿

原 `normal` 策略和上表的负结果完整保留。另加 `adaptive-mining`：本地 40 格内有需要的可达矿石时沿用原选择规则；没有时才扫描全图，按实际可达路径长度选择远矿。仍由散工走路、开采和搬运；不修改地图、库存、工人数或消耗，也没有任何种子专用分支。

种子 23 补救结果 **6/6 通过**：五年末 20 人、0 死亡、食物 359.2、柴火 0、工具 31；饥饿人日与工具断供均为零。它验证了正常操作确实能够解决远矿问题，而不是仅用脚注解释失利。

补救规则冻结后，再选择新的独立种子 33–40，同时运行两种策略，结果 **94/96，未全部通过**。两策略各 47/48，结果完全一致：七个种子零死亡，第 40 种子第一冬冻死一名未安置儿童，其余食物/工具指标通过，全部活满五年。未为新种子降低寒冷或更改阈值。
