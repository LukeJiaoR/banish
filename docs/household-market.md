# 真实家庭配送与市场（v0.3.57）

## 如何开始

新游戏和没有配送字段的旧档都保持“自动供给”：每天仍从公共库存吃饭、烧柴。
在市政厅或市场查看“全村真实配送”，先导出当前存档，再查看逐类、逐户的实际划拨预览并二次确认。**该存档只能单向启用，不能切回自动供给。** 取消预览不扣货、不改变模式；载入其他存档或家庭、公共库存、政策变化会使旧确认失效。

切换当次，从公共库存划入最多两日口粮；秋冬另划入最多两日取暖燃料。三类食物按现有比例、各住处人数分配；粮少时所有家庭按同一比例得到更少的实际口粮，不凭空补足两日。柴火优先，允许煤补柴时才使用公共保留线以上的煤。界面逐类列扣除和各住宅/临时补给点的分配。只执行一次，读档不重新发放。这是为了兼容已有村庄的显式存量迁移，并非平时配送规则。

## 实际生活链

- 公共仓库 → 货商携货 → 市场现货 → 家庭采购携货 → 住宅食品/燃料 → 实际食用/取暖。
- 市场为 3×3，最多一名货商；货商每趟最多 80，家庭采购最多 40。市场容量 240，普通住处上限 350。目标按附近住户需求和季节自动计算，不能另存生产材料。
- 市场方形范围为中心原点距离 18 格。住处优先选择范围内有合适现货、且路径可达的市场；否则去可达仓库。堆料场仅能提供柴火/煤，不能领食物。所有实际路程都使用现有加权寻路、道路速度、携货速度和冬季速度。
- 市场目标、服务范围是供货计划，不保证到货。零货商停止补货，现货仍能采购；附近仓库可能比绕行市场更快。搬货不增加产量或食物总量。
- 家中储备低于两日时，健康成年劳动力在当前工作/携货完成后采购，目标约四日。仍在上学的学生不负责购物。一次每个住处仅一项采购计划，实际在途货占用目的容量。工作成人暂时离岗采购，教师不在校就不能教学，原岗位不会凭空补出第二个人。教学/医疗值守/酒馆接待等无穷服务在值守每两小时或清晨续接时检查采购需要，不必先挨饿；真正生产批次和实货仍需完成后才购物。
- 没有健康成年采购者的家庭可由健康空闲散工帮忙；不抽走教师/医生等在岗者。无房家庭在实际所在位置建立不保暖的临时补给点，依然需要真实搬运，不能远程从公共库存吃粮。
- 三类食物及每人每日需求不变，住宅只有送到家的柴火/煤能用于取暖。煤的公共工业保留线在出库时检查；已经送到市场/家中的煤不会二次扣公共库存。关闭煤取暖后停止使用，闲散成人可将现有煤实际退仓。

## 迁居、中断与损失

食品/燃料留在物理住处，不跟随家庭身份瞬移。搬迁中的采购者会携原货到新的有效住处/临时补给点；原家庭消失时改为退仓。宿舍按当前所有入住家庭共享实存食品和一次取暖，单户搬走不会搬空别人的储备。

空屋、拆除住宅/市场、改建时留下的存量，以及死亡配送者遗留的货，成为原位置可回收物资。空闲成人实际搬回公共仓，或新的采购者在可达处领取。原料退款与生活存量分开，重复拆除没有二次返还。已经生产的普通旧版物流规则不在本次改动范围内。

供货/目的路径中断会保存同一批货并间隔两小时重寻；仓满退货保留余量，不丢弃。若等待退仓者自己的家庭已不足一日口粮，会将货放成原地可回收物资，腾出双手采购；物资不会凭空进入公共库存。

烟警迁出后，原屋存量封闭，扑灭后重开；确实烧毁时才销毁原屋剩余物资并记录损失，已经搬出的货不受影响。重建新屋不恢复被烧掉的货。没有通路、空闲人力、现货或足够供应能力仍会造成饥饿/冷屋，市场不是免费供给。

## 库存与流水口径

公共库存只包括可以供贸易、作坊和建设使用的公共资源。市场、家中、临时补给点、在途和散落回收物资单独展示；火情封闭库存另列。粮食/柴火自动生产目标、全镇储备预警考虑已经分发且未被火情封闭的生活存量，贸易和工业仍只能扣公共库存。

公共流水余额仍是“期末−期初 = 实际入库−公共消耗−公共领出”。家庭配送领料计领出，退仓计入库；家庭实际吃饭/烧柴另计 distributedUsed，火毁另计 distributedLost。实际生活消耗显示为公共消耗加家庭消耗，不能把领出再算一次消耗。发展挑战同样使用真实公共+家庭食用量。旧流水缺少新增项时只补零值，不捏造旧配送历史。

存档保留模式、逐处存量、五类混合实货、临时补给点、回收物资和实际使用/损失。既有任务不保存的合同不变：未取货计划重启，已取货仍属于原配送者并继续送达或退回；旧世界实体不能操作新局。

## 与原版的关系

[Banished Wiki — Market](https://banished-wiki.com/wiki/Market) 的核心是货商集中从仓库补货，居民领取食物和柴火带回家，并优先使用范围内市场。本片继承该因果链；3×3 占地、一名高效货商、容量 240、80/40 每趟携量、18 格范围、四日目标/两日起运、临时补给点、散工帮助和启动划拨是本作小地图适配。不是原版 25 人、10,000 重量容量与直径 90 格的数值复刻。0.3.57 首版不加入衣服、工具或生产原料；0.3.59 可另行明确启用[衣物配送](clothing-supply.md)，工具和生产原料仍未加入。

## 已测边界与观察

1. 组件同布局、五人两家、400 游戏小时，预先从公共库存划出四日口粮：远仓无市场总采购 335.9h；有市场家庭 163.7h + 货商 143.5h = 307.2h，总时间约下降 8.5%。近仓无市场仅 35.6h，绕市场后合计 82.4h。时间包括取货、走路、等待、卸货，不是纯行走；不能转称固定产能加成。
2. 种子 1 的真实新局、正常建造策略、没有免费建材/建筑/预置市场，跑到第 48 日：自动供给零死亡/零饥饿人日/零冷屋日；最终候选直接启用未划拨原型零死亡但 7 饥饿人日；正式两日存量划拨后零死亡、零饥饿人日、零冷屋日。这只是一种子/策略，不能推断任意布局安全。早期版本分别出现 8/3 饥饿人日的记录也保留，单变量 A/B 已复现：同一启用后快照、同房址和策略，仅恢复“伐木屋只看公共柴火”就回到3饥饿人日（第24日同屋3人）。新口径计公共+已配送柴火，产柴162→144、第三屋开建21→20日。但伐木岗位占用345.25→401.25h、采购475.75→491.5h，因此绝不能将这一次零饥饿包装成整体效率提高或固定增益，没有改速度或粮食产量。搬迁和采购仍有成本。三种路径的建造/出生日期不同，不能称相同执行轨迹。
3. 五类物资逐步守恒、实际道路移动、公共抢料、死亡/拆除/改建、迁居/无房/孤儿帮助、扑灭/烧毁、煤保留与退仓、反复读档和无效存档原子拒绝均有聚焦检查。
4. 使用实际 Canvas 绘制和 DOM 检查，未做真实浏览器或手机试玩。离线画面不能替代人的操作与性能验收。

## 配送库存显示修正（v0.3.58）

- 顶栏“配送在途”计入同一篮中的每种实货，三类粮相加显示总食物；这部分已经离开公共库存，送往市场、住处或退仓，不是新生产。普通待入公共仓产物仍另列，不再把家庭配送的主货重复标作“待入库”，也不遗漏篮中其他食品和燃料。
- 生产目标页分别显示公共库存与实际目标计量。真实配送时，食物各类/合计和柴火目标计公共、市场、住处、配送在途及待回收实物，排除火情封存；煤等工业目标仍只计公共库存。公共库存为零时，家中已有口粮仍可能让生产目标暂停，显示现在解释其原因。仓容只约束公共仓，不能由“总目标高于公共仓容”推断一定要扩仓。伐木屋沿用相同柴火计量说明。
- 启用预览保留实际逐项划拨数量，足额两日粮的极小浮点尾差不再触发“库存不足”；真实不足仍提醒。

这是既有规则的只读信息修正，没有增加生产、改动搬运、放宽仓容或改变默认供给模式。42 项家庭配送 DOM 与实际 API 检查、8 项生产目标 DOM 检查通过；新断言覆盖真实混合取货、退仓标记、普通产物并存、足额/不足预览和只读目标计量。真实浏览器/手机仍待试玩。既有采运反馈测试的截取式 UI fixture 缺少 mineralBuildRisk，在合并前基线上同样失败，不将其宣称通过。
