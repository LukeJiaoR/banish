# 建材实运与工地供料（0.3.71）

任务：[Issue #79](https://github.com/LukeJiaoR/banish/issues/79)。在 0.3.70 / main `1ea5848346e4707620d111660ff5eacb5e1b0eb5` 上补原先缺失的建材运输环节。本文位于未合并分支时仅描述候选，交付以普通 PR 合并为准。

## 玩家能做什么

新工地要先清场，再由工人到可达仓库或堆料场领取木、石、铁，背回工地。全部建材实到之后，才开始原有施工工时。仓库位置、道路速度、被堵住的入口、多个工地竞争同一批库存，都影响实际完工时间。

工地详情逐项显示“需要 / 到场 / 在途 / 已投入 / 待领”，以及清场、缺料、运料、暂停和施工状态。居民详情说明正在领建材、送到工地，还是将未用建材退仓。沿用原工地和人物抱货素材，没有新增建筑或重绘美术。

- 创建工地仍检查当时公共库存是否够全价；这是兼容现有放置预览的本作限制，不是原版无限蓝图规则。
- 确认只创建工地，不提前扣除或预留库存。真正到仓领取才扣库存；别的生产屋或工地可能先使用它，后来者缺料会等待。
- 使用现有最多四名建筑工人完成清场、搬料和施工，不新增全局职业分配系统。单趟最多 20 单位、取料/交料各 0.1 游戏小时是本作运输节奏适配，不宣称原版重量公式。
- 木桥也须从实际岸边运料，完工前水面仍不可通行。木屋升级把旧屋可回收建材直接留在原址，仅补料须从仓运入；烧毁住宅重建没有旧材抵扣。
- 免费开局建筑仍免费；即时土路和石路铺设沿用既有规则。本片没有改变逐仓库存：公共库存仍共享，兼容收货点由仓库/堆料场类型决定。

## 每批材料归谁

1. 尚未到仓的任务只是计划，不扣库存，也不预订材料。
2. 领取时重新检查真实库存、目的工地与尚缺数量。该批材料从公共库存移到携带者身上，并记住工地身份。在途实际货批参与需求计算，多个工人不会把同一缺口重复领取。
3. 必须真正走到可达工地入口，才把随身货物移入工地。库存不会因为工人远程完成任务而增加；暂停、失效任务不能偷交货。
4. 备齐后，首次实际施工把到场材料一次性投入建筑。后续施工小段、过夜、保存或再次派工均不再扣料。

核对原则：对单种资源，公共库存 + 实际携货 + 工地余料 + 存续建筑投入 + 已记录不可回收损失，在运输/投入/回收过程中守恒。拆除退款是已有材料从工地或建筑回到库存，不能再把相同在途货重复退一遍。

## 暂停、取消及意外

- 暂停保留已完成进度和到场建材，未领取计划停止。已经接受的货批仍属于携带者，转为实际退仓；恢复后只补真正缺口。
- 改派工人、工地被取消、读取后不再保留原工作任务，都不能删除已经领出的建材。货批单独实运退仓；仓满、没有仓库或道路中断时仍留在身上等待。
- 新工地尚未实际施工，取消只退其实际到场材料，尚未领取的计划退零。在途材料不在立即退款内，之后由携带者送仓。
- 已开始实际施工或已完工的建筑沿用一半回收、向下取整的适配；另一半计为不可回收损失。旧档曾清场开工的半价退款合同单独保留。
- 回收沿用本作的即时返公共库存，不新增拆解运输、地面废料堆或独立仓库账。本次解决的是建材入场运输，不能把回收适配写成原版完整拆除物流。
- 搬运途中死亡，精确记录剩余建材损失；不能给工地补发免费材料。工地仍需由其他人重新领取真实库存来补缺。住房烧毁和升级的未回收旧料也应落在明确的损失口径内。
- 取消、升级和拆除不能反复执行退款。升级一经确认，木屋和居住条件立即改变，取消石屋工地也不会把原木屋复原。

## 旧档与保存

0.3.70 及更早的工地早已一次性付清成本，因此载入后视为建材已到场，保留其施工进度、清场标志、暂停、优先级和旧的全额/半额退款资格；不要求再付一遍，也不倒退施工。以后新放的工地走同一运输/施工流程。

新档保留所需材料、到场材料、是否已投入、实际标记携货和已记录损失。和原存档一样，不序列化完整工作任务与路线；读档后原未用建材安全退仓，再由调度补缺，不宣称逐帧重放。非法数量、混用不相容货物身份、损坏的工地状态在替换当前村庄之前拒绝。

旧成品建筑、免费开局、原来已领取的贸易/生活补给/工业原料/猎获/牧场产物不改名、不转成建材，也不再次扣库存。

## 原版依据与验证边界

- [Banished Wiki：Builder](https://banished-wiki.com/wiki/Builder)：先由散工把所需材料放到工地，齐料后建筑工人施工；可以暂停工程。
- [Banished Wiki：Laborers](https://banished-wiki.com/wiki/Laborers)：散工承担清场、送原料入库，以及仓库到工地的材料运输。

原版职责分工有依据；本作合并岗位、共享仓库、运输批量、已有成本工时、取消回收方式仍是适配。没有引入新气候、经济平台、分仓物品账户或部署流程。

定向验证入口：
- `node tests/construction-delivery.js`
- `node tests/construction-delivery-ui.js`
- `node tests/construction-delivery-render.js`（既有抱货/装卸姿态与尺度派发，不是视觉验收）

另复核受影响的旧档、房屋升级/火后重建、木桥、工地暂停与优先级、清场/完工入口和基础启动。实际通过项和独立审查结果写在 PR；模拟/DOM 检查不是浏览器或手机视觉验收。
