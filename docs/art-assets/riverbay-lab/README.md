没有调用图片生成模型或重新绘制草贴图。低频地面是一个 256×256 的确定性代码色域，世界坐标覆盖 64 格后重复；它只用于检验大色块密度，不能当作新的手绘美术。水仍沿原框架每 8 格重复。

岸线提取水陆边界，按连通边追踪路径，二次曲线连接、分层绘制。湿沙裁在陆地，浅水裁在水域；泡沫是低透明度稀疏短线。路径连续并不等于视觉无阶梯：原沙滩格与水陆裁剪仍来自原网格，当前画面仍明显受其限制。

杂物是低透明度小椭圆/枝条，候选密度 7.5%，避开建筑、树、道路、岩石、临岸格等；不加入可采集对象或碰撞。

所有静态候选都烘入原来的单张地面缓存。额外仅有一个 256×256 色域画布，没有三张全地图分层画布。脏区先裁剪/清空，再重画局部，避免透明图层重复叠加。更换世界、缓存比例或候选选项会全刷；直接修改水体拓扑的测试应显式调用 `invalidateTopology()`，本样板不提供改水玩法。

## 美术结论与待验收项

实际看过上述原生图后，**本轮仍不通过美术验收**：

- 水 v2 较安静，但 8 格重复结构仍在，尚不能证明长时间观看无平铺感。
- 三层颜色比原细硬边柔和，但沙滩格、水陆 mask 的阶梯轮廓仍突出；没有实现自然连续曲线岸形的最终效果。
- 低频地面降了黄斑密度，却显得过平且局部可见格缝。色块研究不能代替新的手绘笔触素材。
- 现有建筑、树完全保留；没有把人物/UI的审美意见扩成这次实施范围。

浏览器验收已补（2026-10-17，真实 Chromium）：页面加载、四个预设、开关、拖动和窄屏布局均正常，`window.__errs` 为空。结论仍未通过——`lowFrequency` 开启时 `fillLow()` 直接替换 `originalTile()`，完整研究里没有草贴图，只剩平色域；`tileMask()` 按整格菱形裁剪湿沙/浅水带，底层沙滩格仍是网格形状，2 倍放大下锯齿明显。切换完整研究首帧约 236–283ms（`buildGround` 仅 2–9ms），暖帧 p95 约 0.6ms；这是单机单轮数据，不是手机性能验收。实体手机、热量、帧率、触摸手感和长时间游玩仍未验收。详见 [浏览器验收记录](browser/browser-acceptance.md)。

进一步采纳前至少需要：

1. 真实浏览器的同场景、日光、镜头和 0.75/1/2 逐项 A/B 已补（见浏览器验收记录），结果仍不通过：草地没有贴图、岸线锯齿。下一步需要先做出可用的草地与连续岸形，再由使用者确认美术方向。
2. 要获得新手绘草地笔触，需要另行制作/授权新的素材；代码可继续处理更合理的低频分布、岸形 mask 与地面装饰，但不能冒称重画了贴图。
3. 保持原单缓存及 1600 万像素预算、暖帧不重建、脏区无累积。已记录一轮浏览器冷切换（236–283ms）与暖帧 P95（约 0.6ms）；仍需 30 秒以上平移/缩放 P95、实体手机复测和触摸/热量检查，当前数据不足以通过此项。
4. 先保留独立候选入口。待视觉、真实浏览器及性能同时达标，再单独评审是否接入正式游戏。
