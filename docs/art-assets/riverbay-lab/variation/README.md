## 怎么比较

原独立入口 `riverbay-lab.html` 中，选“纹理叠加研究（A）”和“岸带宽色变化（B）”。两者只有第五开关不同：原草纹理、26% 低频叠加、水 v2、连续水陆 mask、杂物、场景、镜头和光照均一致。还可单独切换“岸带宽色变化（需岸线）”；未开岸线或处于冬季时不生效。默认五项全关，旧四个预设仍明确关闭新开关。

## 变化设计

- 原版等宽沙/浅水描边继续保留在 A。B 用跨 22/26 格尺度的平滑正弦组合控制宽度，基础湿沙宽度 4–14、浅水 6–18 个世界屏幕像素；叠加较浅外层和内层，最大外带为 18.8/23.6 像素。输入是世界格坐标，缩放和平移不会重新随机。
- 颜色是同一世界坐标下的低频五节点渐变，在克制的灰绿、暖沙色之间平滑变化；没有逐格随机污点或新的高频颗粒。原泡沫仍为稀疏低透明度短线。
- 直接采样已有连续二次曲线，形成可变宽单侧带，再使用原闭合水域/反向陆域 mask 裁剪。所有相邻截面以同向三角片一次 nonzero fill 联合填充，避免小池塘偏移环翻折后相消。地图出口有圆端帽，避免斜边楔形缺口；没有恢复逐 tile 水陆裁剪。
- 不改原水陆拓扑、道路/岩石 footprint、碰撞、寻路、建筑/树/人物或正式素材。没有新生图或新草贴图。`index.html`、`js/`、`assets/` 不变。
- 复用原单张地面缓存和 256×256 低频色域；只增加随岸线长度增长的曲线采样数据，没有新增全地图画布。原 68px 连续恢复带与局部修补 halo 保留。

## 本轮测试结果

- **29 组地表测试通过**：23 组零依赖契约 + 6 组 native 像素，含旧版全部 18 组。原四季绘制指令 SHA 与 `2857b94` 相同，未开岸线/冬季的新开关是全绘制和脏区 no-op；宽度范围、连续性、同 seed 确定性、共享曲线/闭环、世界坐标、碰撞/RNG、缓存预算均保持。
- 审查捕捉并修正了小池塘偏移环相消、地图开口端帽楔形漏色。新增测试直接检查真实 gradient fill 的 winding，而不只检查辅助公式；池塘/陆洞/窄渠/四边出口均覆盖。独立复核 11 种几何、3,576 个带内点，没有漏色。
- B 的 51 次编辑/153 次重复修补逐字节稳定，**实际修补矩形外变化为 0**。与独立全刷参考比较，局部最大差 8、平均通道差 ≤0.0859；远处 AA 最多 8 像素/2 色阶。原内部 ≤32 / 不同像素≤12% / 平均≤0.25 和参考外侧 ≤16 像素/≤2 预算均未放宽，真实越界写入仍必须为 0。[完整地表测试输出](pixel-tests.txt)
- 控制器 12 组、计时器 8 组，以及 ground-cache-budget、terrain-presentation 8 组、mountain-render 10 组通过。语法及 diff 检查通过；不是 GitHub CI 全绿或完整经济回归声明。
- 20 例 × 30 暖帧都为 0 地面重建。完整 world/game 玩法快照不变；原渲染器的 46 项显示缓存变化仍逐项披露，未写成全部状态零变化。16MP 缓存预算不变，没有新增全地图画布。

## 性能与后续验收

重型测试与其他项目串行执行。本轮共享 VM 的 native 桌面 1 倍，A 整个同步帧调用 **142.331ms**，B **164.202ms**；B 内部帧段 164.145ms，构建提交 **57.617ms**、首次地面 drawImage **104.592ms**、其余 **1.936ms**。B 的六个尺寸/缩放冷帧为 **150.4–166.3ms**，暖 P95 **1.31–1.96ms**。这是单轮观察，B 增加了构建开销，不声称性能优化或零卡顿。

该 native 数据不能与用户 A 的真实 Chromium **32–48ms** 直接换算，更不能据 drawImage 同步时间判断 GPU 原因。B 尚需相同镜头/缩放下的真实浏览器 A/B、开关/窄屏/拖动验证与分段计时，再决定宽色方向是否值得保留；30 秒交互 P95、实体手机热量/触摸/实际帧率和美术确认仍未完成。继续 Draft，不自动采纳。
