## 结果

### 1. 完整色块研究（lowFrequency + clutter）

**草地纹理被整体替换，而不是叠加。** `tools/riverbay-lab/terrain.js` 的 `drawGroundTile` 在 `lowFrequency` 开启时走 `fillLow()` 并跳过 `originalTile()`，所以“完整研究”里没有原草贴图，只剩 256×256 代码色域 + 稀疏杂物。浏览器里表现为一整块平绿；原版的细草纹理、明暗颗粒全部消失。`grass-compare.png` 是同机位 1:1 对照。

色域均值约 `112/126/75`，原夏草贴图均值约 `100/121/53`：研究稿更亮、更黄，进一步放大了“平”和“发白”的观感。它只能证明色块密度，不能当作草地候选。

### 2. 三层岸线

三层颜色确实比原版细硬边柔和，但**阶梯是结构性的**：

- `tileMask()` 用整格菱形裁剪湿沙/浅水带，色带在每格边界被切断；二次曲线路径只负责描边，不负责裁剪。
- 底层沙滩格与水陆 mask 本身仍是网格形状，所以即使把色带画成连续曲线，露出来的仍是锯齿沙滩。
- 2 倍放大下（`shore-closeup-z2.png`）可以看到连续的菱形锯齿、三角缺口和被切断的湿沙带；不是“还差一点”，而是当前实现无法消除。

### 3. 水 v2

水面明显更安静，岸边没有看到新的接缝；8 格重复在本次视野内未形成明显花纹，但未做长时间/大范围观察，不能据此通过。

### 4. 浏览器性能（单机单轮，不是手机数据）

在页面内对 `setOptions` 计时，重复切换预设：

| 切换 | 总耗时 | 其中 buildGround |
|---|---|---|
| 原版 | 12.2 ms | 0.9 ms |
| 水+岸线 | 23.4 / 18.0 ms | 4.7 / 2.7 ms |
| 完整研究 | 283.3 / 236.3 / 241.6 ms | 8.5 / 2.4 / 2.8 ms |

完整研究的切换卡顿约 **236–283 ms**，但 `buildGround` 只占 2–9 ms；其余时间发生在首帧呈现/栅格化阶段。暖帧 40 次连续 `render()`：p50 0.3 ms、p95 0.6 ms、max 0.7 ms。也就是说稳态很轻，问题集中在切换/缩放/全量重绘后的第一帧。这个数字与 PR 里的原生冷构建 ~110 ms 同一量级，但不能当作浏览器或手机的性能验收。

## 结论

- 浏览器可见性、布局、开关、拖动、控制台：**通过**。
- 美术：**不通过**。草地研究稿是纯色域，不是可用草地；岸线阶梯未被三层色带解决。
- 性能：稳态通过，切换首帧有明显卡顿，需在真实浏览器和手机上复测。
- 真机（实体手机、热量、帧率、触摸手感）仍未验收。
