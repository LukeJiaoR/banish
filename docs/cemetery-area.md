# 可变墓园与拆围栏留墓（0.3.73）

任务 [#83](https://github.com/LukeJiaoR/banish/issues/83)，基于0.3.72。此片只补土地规划与墓位占地，不加入祭扫闲逛、幸福光环或新的殡葬职业。

## 来源、公式和适配

[Wiki墓园页](https://banished-wiki.com/wiki/Cemetery)写明每边7–20，拆墙不会移除墓碑。[开发者说明](https://shiningrocksoftware.com/2013-09-18-cemeteries/)确认墓碑自然衰败后才可重用该空间。

[Wiki链接表](https://docs.google.com/spreadsheets/d/1brX36N8UBwX4PtnPAH0y75PIXs_xr8OQ59tUVyXhNSk/edit)中的“Stone And Work Cost”和“Number Of Graves”两张14×14有效尺寸表，均已完整读取。由196个数值逐项复算得到：

- 石材与劳动量分别为 `2×(横边+纵边)−4`，不是面积成本，没有木材要求。
- 墓位数为 `(横边−4)×floor((纵边−1)/2)`。
- 7×7：9位、24石、24劳动；7×8：9位、26石；8×7：12位、26石；20×20：144位、76石。

公式是对整张已发表数值表的等价推导，表中存储的是数值，不是作者公式。表轴没有世界方向标签；本作明确把表横边映射地图x、纵边映射y，不声称已核实原版罗盘方位。新园墓碑按横向一格、纵向两格的稳定槽位排列，具体留白与脚点是本作适配；预览点与实际墓碑位置一致，换向确实会改变容量。

[官方1.0.7工具包](https://shiningrocksoftware.com/download/BanishedKit_1.0.7.170910.zip)的 Cemetery.rsc 确认两轴7–20、只需石材、劳动量随尺寸缩放，帮助文件描述石材按围长计。Tombstone.rsc的寿命字段为60个月、容差12个月；未核实其随机分布和引擎换算。本片继续采用192游戏日墓期及现行哀伤数值，明确是本作适配；劳动数值沿现施工小时尺度，不引入新时钟。

## 玩家流程

1. 选墓园，拖矩形或点两个角，预览实际槽位、容量、石材、工时和清树数，再确认创建工地。没有常驻岗位。材料不会在预览或放置时远程消费，工人实运到场后才施工；工地暂停、取消与在途退仓沿既有规则。
2. 完工后，死亡时仍按现道路时间成本找到实际可达的空墓园。登记占用唯一墓位并显示原墓碑素材，不做尸体运输。空间不足的原有亲属哀伤规则不变。
3. 拆围栏前显示保留墓数、所占格、释放格、最晚到期和实际返料，再明确确认。此后不接新安葬；已有墓碑姓名、身份、位置、原到期日保留。空地释放，只有墓碑所在格继续占地，不能被新建筑、道路或新墓园覆盖。
4. 残墓可点击查看来源与剩余期限，不可主动建造、拆除、退款或复用墓位。保留墓园原本可步行的合同，旧道路不因拆墙或到期被抹除；“不可建造”不等于新增行走障碍。到原到期日只释放该墓拥有的占格。

## 旧村与所有权

没有 `cemeterySize` 的旧园仍是4×4、8位、16木40石、80工时。原施工进度、实际材料、已有墓位编号/脚点/姓名/到期日和居民哀伤保留，不把旧园挤入新的槽位公式，不追溯追加死亡或幸福变化。

拆园退款只发生一次，按现建材实运的实际退款权益计算；残墓没有建材权益。旧按钮、旧对象、墓位或日期已经变化的确认不能重复退款或抹墓。已接受的施工携货仍由搬运者拥有，拆园不重复计入退款。保存读取验证新尺寸、实际占格、墓位身份/来源/期限和重叠，非法状态在替换当前村庄前拒绝。

## 美术和验收口径

复用现有墓碑、围栏与地表，没有新生成贴图；墓碑仍16×17显示，旧脚点不重排。规划仅画实际槽位标记，拆园后不保留虚假的围栏和整块院落。

针对性验证覆盖196尺寸/成本公式、实际施工、旧档、拆除确认过期/取消/重入、残墓占格与道路/建造/步行、自然到期、保存恢复、重复退款和原哀伤回归。离线绘制和DOM验证不等于真实浏览器或手机验收；最终审查、远端状态及验证结果记录在关联PR/Issue。
