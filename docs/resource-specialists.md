# 少人高效的资源小屋（0.3.21）

## 选择与范围

采用“专业工人更高效、减少占工、保留运输与扩张成本”的两倍档。每工效率提升不等于全镇吞吐翻倍；释放的工人仍会被调度去建设、采集、其他岗位或闲逛。

|建筑|原岗位→现岗位|本次规则|
|---|---:|---|
|采集小屋|4→2|基础每趟5→10食物，成熟林折扣不变|
|猎人小屋|4→2|满林每趟5→10食物，成熟林要求不变|
|渔码头|4→2|满水域每趟4→8食物，作业5小时不变|
|深井矿|4→2|每批3→6石/铁，9小时及通常每5批1批铁不变|
|护林小屋|4→2|专业砍伐8→4小时、补种3→1.5小时，连续采树后最多8原木一批|
|伐木屋|1→1|加工7→3.5小时，仍2原木→6柴（受教育8）|
|铁匠铺|1→1|加工8→4小时，仍2木+1铁→2工具（受教育3）|
|农田|4→4|季节播种/收割、单格产量和搬运批次不变|

菜单岗位数与实际派工都使用新上限。施工期间仍可有4名建筑工；完工才切换专业岗位。木屋是住宅，没有这些生产岗位。学校不变。

## 护林与资源守恒

护林在自己的作业范围内优先选择工人附近可达的真实成熟树；每棵仍产2原木，受教育产3。每次砍伐和原地补种都消耗实际工时，树木成熟速度及保留成熟树下限不变。普通手动砍伐和工地清树仍使用原8小时规则。

护林工最多携8原木，受教育者两棵得到6原木就送仓，不截掉第三棵的产出。最后一棵、关闭砍伐、达到木材目标或换岗时交出尾批。活动任务及夜休暂停任务都认领同一棵树/种植点，其他工人不重复认领。

可达检查是单次派单内有界、按需扩展的连通扫描；真实行走仍用原A*，没有跨日缓存。不可达的最近树不再使整屋反复失败。森林与采集/狩猎共址仍会相互影响，不能把专业效率当成无限成熟林。

## 旧存档

完成的五类4→2岗位建筑按原工人顺序保留两个，释放多余岗位；不删库存或在途货。已有存档规则原本不保存活动任务进度，读档仍按该规则重接任务，不声称本次新增任务进度持久化。施工工人不提前截成2人。

全镇生产目标、原伐木屋燃料目标、铁匠工具目标沿用旧值；0仍停止新自动生产，已开始和在途批次继续。没有默认开启新目标、没有改变硬仓容。石/铁满仓保货规则保持；其他资源满仓交货仍可能丢弃，工人死亡仍按既有规则处理背货，本片没有扩大这些承诺。

## 组件证据与取舍

先固定预建建筑、岗位、充足原料/食物与大仓容，关出生及寒冷，保留真实走路、冬季移速、工具磨损、工作、夜休、搬运和生长。组件不是城市生存证明。3种子近/远仓、5年，取第2–5年平均；下表是0.5游戏小时步长的近似每屋年产。

|建筑|近仓原→两倍档|远仓原→两倍档|
|---|---:|---:|
|采集|1018→1023|577→588|
|猎人|1139→1138|567→582|
|渔码头|1681→1676|494→493|
|矿井（石+铁）|806→806|291→291|
|柴火|288→490|139→164|
|工具|147→243|51→64|
|护林原木|235→286|169→256|

- 正常采集/猎人/渔/矿整屋约保持原产能，每工约2倍。近仓加工明显受益，远仓柴/工具约75%/82%清醒时间用于运输，提速不会消掉路程。
- 缺工具取整有差异：旧5×0.5四舍五入为3，新10×0.5为5，因此两人采集/猎人整屋约旧版84–86%；矿井约75%。低水域渔获也有取整台阶，相对旧屋约83–125%。仍需工具、合适选址与运输。
- 另比较了食物每趟3倍档：整屋约旧版145–154%，会形成更富裕的粮食节奏。本版未采用，原因是用户目标可由少占工的两倍档达到，不能仅以某个固定脚本更高存活率选择增产。
- 原组件审计182主样本、48步长复核、36边界断言；230场库存/投入/进食磨损/溢出/在途守恒全部通过。更细0.125小时步长的绝对产量最高变化14.6%，故表格不是精确玩法保证。

## 城镇与性能验证边界

生存对照基线统一为含夜间通勤修复的0.3.20，不混用0.3.19来归因人效。固定40局5年包含正常、原始开局、放任、不产柴、过度扩张；另测多种子12年正常扩产及码头开局、保留独立种子验证。[完整数值与逐年曲线](resource-specialists-verification.json)保留成功及失败样本。

- 40局固定矩阵：65/65验收断言通过。正常8种子两版本均无死亡；人效版期末人口22–27，基线19–24。
- 独立种子17、23、29、33、42、55、81、97：5年48/48断言通过，均无死亡；基线47/48，种子55首冬死亡。
- 种子1、2、41、65、73、74，两种真实付费开局再长期扩产共12局12年：本版12/12无死亡；基线有3局灭村。不是保证任意开局都能存活。
- 错误决策仍有代价：过度扩张本版8/8灭村，基线6/8灭村；放任两版8/8灭村。不产柴本版合计115人死亡，基线120。没有为了全绿删掉压力场景。
- 最终源码另跑140个组件场景，资源账目守恒；旧档迁移、认领、尾批及不可达边界另有定向回归。

曾出现的“直线近、绕行长”夜返循环已独立在0.3.20修复。没有通过关闭饥寒、免费造屋、强抽粮工或修改固定策略断言让人效测试通过。组件与脚本生存不能代表真人觉得好玩。

路径计数显示护林的减少折返抵消了新可达扫描成本；病理薄林不再反复尝试同一不可达树。释放劳力可能增加闲逛、人口增长会增加模拟工作，不能声称全应用CPU、手机帧率或耗电已降低。实际正常城镇种子1、5、41五年，寻路调用较基线增加7–14%，地块检查增加7–18%，闲逛寻路增加61–75%；这是人口与劳动力行为变化，不是CPU计时。真实浏览器/手机仍未验收。
