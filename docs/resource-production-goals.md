# 全镇自动生产目标

本功能不修改任何产量、成本、人口消耗或仓储数值。新局和旧档均默认未设置，全镇未设时保留旧规则；各伐木屋的 fuelLimit 和铁匠铺的 toolLimit 不合并、不覆盖。

## 语义和验收边界

- 六项资源分别设目标。库存达到目标停止接新自动生产；已接任务、已付原料和在途货物继续处理，库存不会被目标截断。
- 恢复线 = 目标减去10%（向上取整，差额至少1、至多100），库存降至恢复线或更低恢复。0明确关闭新的自动生产；“继承原规则”删除全镇配置。
- 柴火和工具取全镇与本屋旧目标较低者。只有配置了全镇该资源目标才启用本屋滞回；详情解释有效目标和来源。本屋旧值不被全镇操作更改。
- 食物统一控制采集、狩猎、渔业。农田在本季第一份播种任务生成时承诺整田；正在执行/暂停的首次播种、旧档已经播过的任意一格也算承诺。之后继续播完和成熟收获；只限制尚未开始的新季播种。春季重置承诺。已启用食物目标时，季节重置也终止旧季未完成的播/收任务，不能拿旧挂起任务绕过新季目标；已经收获在身的粮食保留。作物仍按原季节生长、未收仍冻死，目标不赠粮。
- 木材目标停止新护林砍伐；开启补种时继续育林。矿井分别判定石头、铁，只有两项都暂停/满仓才停止。
- 手动标记采伐、采矿和建筑清场不受自动生产目标限制，建筑不会按未来产物目标停建。
- 调度沿既有两小时周期，交货事件同步暂停状态；UI读取不触发调度或全图扫描。配置改动不直接取消工人任务。因目标暂停的岗位在途/在做/挂起任务完成后才进入通常空闲释放和派工。其余劳动竞争仍沿用旧调度。
- 批次保护仅适用于当前任务的实际暂停产物。石头暂停不锁住未暂停的铁矿任务，木材暂停不锁住新的补种任务；粮食紧急状态仍可正常抽调这些工人。改全镇值但本屋有效目标不变时保留本屋恢复线状态。抽调时跳过受保护者继续找其它合适工人。
- 硬仓容单独显示。允许目标高于硬容量，明确警示；本功能没有修复既有满仓时交货溢出丢弃问题，也不承诺目标可使储存超过硬容量。
- 存档校验有限整数0..1,000,000和布尔暂停状态，恢复滞回中间区间，不修改输入存档。当前游戏本来不保存所有任务/RNG，所以不把快照读档宣传为逐步确定性复盘。

## 控制与验证

专用暂停弹窗，六行固定DOM，资源图标复用G.RES，数字输入和大步进按钮、应用及继承原规则，显示库存/硬容量/恢复线/状态。窗口纳入Esc、Tab、键盘和地图输入保护。

测试要求：先失败的专项测试；未设目标固定种子完整结果与对应主线基线严格相等；存档旧屋差异、输入不变性、非法数据及滞回恢复；全部生产类型、手动任务、农田承诺；改目标期间库存和批次守恒（另标既有硬仓容溢出）；DOM焦点/暂停/重复按键；完整既有回归；多冬配置目标的合理策略和明确失败策略成本。

浏览器路由不可达，本地Chromium权限已拒。DOM/Canvas离线测试不能视作真实手机触控或浏览器试玩。

- 先前对e876994的相同40局严格相等证据保留。不能拿施工修复前后的变化误算为目标功能的变化。
- README原回归及施工完成、首冬控制、冬季恢复、服务端安全等29个常规回归命令通过，另跑40局生存矩阵；包含新合入的9项建筑详情焦点测试，并另对最后修改的UI/目标契约重新运行。未修改任何既有经济常量。
- 全资源「差额37、在途40」均验证：调低目标本身不动库存和货物；直接交货仍受既有硬仓容影响，工具可入40，其余只能入37。此处明确保留原有溢出损失，没有合并独立的满仓货物保留候选。

## 固定目标不是生存预设：保留失败对照

所有目标默认未设置，界面不会替玩家填写以下试验值，也没有「推荐成功预设」。

1. 全目标固定为食物1000、木150、石100、铁40、工具40、柴150（柴火实际仍受旧屋100限制）时，种子29五年仅余3人，15人饿死；原基线种子29无死亡。单变量分离表明，仅启用柴150、引入100停止/90恢复的节奏，也能走向这条失败轨迹。第73天增加采集屋、木石长期不足，没建铁匠，随后工具耗尽，粮食产出下降。这是经营节奏改变的代价，不能包装成安全上限。
2. 另一固定组合食400、木100、石60、铁20、工具25、柴150在11个种子（1–8、11、17、29）五冬中有实际目标启停：每局24–92次状态转换。种子17仍在第203天全灭、21人饿死；种子5有3人冻死。生存筛查64/67，不是全部通过。其余记录也保留，不以某一组恰好成功的目标代替验证。
3. 11个种子设置食物0，均第20天15人饿死。柴火0均造成冻死。过度扩张在多数配对种子造成更多死亡。目标不会给粮、木、工具或取暖免责。

`node tests/resource-goals-economy.js results.json` 是透明输出失败的生存筛查，默认report-only；加 `--assert` 会因上述失败返回非零。环境变量 `GOAL_FOOD` 可切换固定食物目标，`GOAL_SEEDS`、`GOAL_MODES` 可缩小矩阵；不要把改变样本或目标后的结果说成原配置全绿。

## 同一失败种子的真实救回

`node tests/resource-goals-recovery.js recovery.json` 保留同一配置、同一29号种子的无人响应对照，并严格断言两条真实成本的恢复路径：

- 等到第108天游戏实际提示工具不足一年。此时木2、石0、铁20、工具5、食449.58、柴92。临时把食物目标调300、柴火调60；追加避开采集林、可达的树木/石头标记（第108天10树+3石，第111天10树，第112天3石，第114天10树）。工人真实采运，第115天付42木24石开建铁匠，第116天恢复食1000、柴150。五年23人、零死亡、工具31。
- 第59天工具剩10时更早为铁匠筹料，同样只调目标、追加真实标记，第98天开建铁匠；五年18人、零死亡、工具31。

恢复没有直接加资源、免费建造、瞬间完成或改工人岗位。仅在第108天恢复旧柴规则、只停柴、只改食物缓冲等较弱响应仍有死亡或全灭，未从记录中删除。降低柴目标也有挨冻成本，需关注取暖告警并及时恢复。

## 调度边界回归

四成人、粮食归零、可生产粮食屋空岗的隔离夹具中，石目标0的矿井和木目标0的纯补种护林屋均能按旧紧急调度转出3人救粮，八天零死亡。正在完成的对应石批次、旧砍树批次与货物仍受保护；新铁批次和纯补种不能因另一产物暂停而永久锁岗。测试也覆盖全镇100→200、本屋40、库存39时仍等到36恢复，以及首个暂停建筑所有工人受保护时继续寻找后续供体。
