# 固定果园的长期产出平衡

本片基于 `f098ed2686c10dd23a1e5d145f8102597d71509e`。新田继续固定8×8，新果园与牧场继续固定6×6。只把**未来新结的单株果实从20调为50**：固定果园9株满成果为450；已经结出的旧果、已采携货、仓库库存均不补发。苹果、梨及旧通用树使用同一单株量，旧通用树仍产蔬菜。

这解决成熟小果园原来满园只有180、相对其四年养护投入偏低的问题；不靠拖大面积提高新果园收益。旧面积果园保留原尺寸与株数，未来也按每株50，15×15的40株理论上限变为2000，仍受实际采收、运距、仓容与季节限制。本片不声称完成所有农业、生存或贸易平衡。

## 原版依据与本作适配

[官方Mod Kit下载页](https://shiningrocksoftware.com/game/mods/)中的 Banished Toolkit 1.0.7 Build170910：

- `resource/Template/RawMaterialApple.rsc` 和 `RawMaterialPear.rsc` 均设置 `_lowCreateCount=50`、`_highCreateCount=65`。
- 本片采用低值50作为基础。本作教育已缩短劳动时间，不再叠加65产量；这仍是本作适配，并非逐项复制原游戏。
- 九株布局、四年有效养护、每株6工作小时采收、12–20年错峰寿命、48日游戏年均保持现状。
- 农田作物、牧场牲畜、居民食量、死亡条件、家庭容量、种子价格和酿酒配方不改。单株采果后仍一次背送整批，所以新批次最多50，工作次数没有因果数扩大而增加。

核对源文件而未执行工具包，也不复制其美术或程序入项目。ZIP SHA-256为 `615d75d111be843c48af2c1544e2a01aea317e26305ec8087b199cf9504ae964`；苹果模板 `0b1c2b4625377dc2d904dd376e2bef607d6d95b5ed026a3856d0b9470303f7f2`；梨模板 `2bc66207c360142eb74cf1a763e24b2086746ef1e21cfcdf1fc91efaa2180c01`。

## 固定建筑的实际采运对照

`tests/fixed-agriculture-balance.js` 使用同种子5、两名成年居民、预置固定地块、住屋、仓库及生存库存。完成布置后按真实调度、季节、劳动、休息、消耗和运输入库跑完整年度。这个**有预置补给的生产实验不是从零建村生存测试**，也没有支付种子、建造或养护等待期的机会成本。

近仓位于(8,8)，远仓位于(26,8)，田园位于(13,8)，住屋不移动。另有远处仓库保证容量，路线仍由游戏选择。两种布局并不保证每项路程指标单调增加，因此不从这个实验推导通用运距效率。

成熟园的54是实际任务剩余工时递减之和，不包括走路、休息、等待，也不是工人总占用时间。JSON另记 `staffedHours` 和 `staffedWalkOrHaulStateHours`：后者是在岗时处于walk/haul的0.1小时采样，包含通勤与回家，可能包含状态切换帧，**不能称精确移动时间或纯搬运时间**。

从空园开始的六年连续实跑：前四年零果，首次结实第216日，第五、六年各实送180→450；六年累计360→900，18次成功入库，养护、种植与采收合计994任务工作小时。成熟等待没有缩短。夹具居民均无死亡，但有预置1600粮/1000柴/1000工具，不能据此声称果园能独自撑过前四年。

零农夫反例：新季450果全部未采而在冬季消失，产出、入库均为0。未采果从来未记为已产出，和“采出后弃货”分列。

### 守恒与损耗口径

- 产出直接观察该建筑的 `recordProduction`；入库分别观察 `deposit` 实际返回值及 `ledgerRecord('received')`，两者交叉核对。
- `discarded` 直接观察真实 `ledgerRecord('discarded')` 事件，**不由产出减入库倒算**。另以实际溢出7入3弃4作正控，并验证保留货物的零接收不会计弃货。
- 年末断言“实产 = 实际入库 + 仍在途 + 事件记账弃货”。有工人的主实验实采后弃货为0。
- 果树日结前后逐株观察冬季/枯尽导致的未采果损失，记为 `unpickedFruitLost`，不混入上述实产守恒。
- 实际入库不等于年末库存；居民会正常吃掉已入库食物。

完整数值与源码哈希见 [实测JSON](orchard-yield-balance-results.json)。

## 旧档与边界回归

- 真正旧聚合档仍以20为每株上限，总量上限仍是180；137按 `[20,20,20,20,20,20,17,0,0]` 分配。没有重排成50、50、37而悄悄减少旧果采收趟数。直接运行时迁移与读档路径均覆盖。
- 旧逐树档保持每株品种、年龄、果实、季号与更新次数；真实main序列化的20果携货保持原值，连续三次读档也不增产。
- 同一已结实季节不补发；下一次尚未分配的新秋季才按50。跨年、季节存档、重复载入均不重复结实。
- 新50果携货在满仓时保留，先收7、余43；撤岗、拆园、三次读档后仍送齐，总入库50、弃货0。
- 51果单株或携货、超过180的旧聚合档仍原子拒绝，不替换当前世界。
- 已有面积果园沿用原几何/岗位。对应实运回归给40株场景增加真实仓库容量以接纳2000果，没有放大仓库参数。

新旧档合同7组、逐树更新15组、面积果园11组、果品酿酒27组、市政流水15组，以及固定放置/作物/输入保存等受影响检查通过；UI为DOM和真实模拟API测试，绘制为离线调用，不冒充浏览器或实体手机验收。

已知基线问题：`orchard-area-render` 前6组通过，末组把合成world的所有字段按字节比较；其缺少 `roadWorkIndex`，预览会惰性建索引，因此候选和未改main都在同一断言失败。这不是本片新增回归，未改道路或渲染代码。本片不声称全库测试全绿。

保留同一候选源码哈希的首冬与反例观察：种子5/49普通策略首冬均无死亡，仍各有两户无房；没有维护的反例均第20天饿死灭村，无燃料两年反例分别8/6人死亡。这些场景没有成熟果园，只说明本片没有关闭生存风险，不证明农业组合全平衡。摘要和策略哈希保存在JSON。无生产部署。
