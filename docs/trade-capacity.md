# 贸易容量与在途占位（0.3.48）

## 已复现的问题

main `fdd2a29038a9d9650a81c3ffd1ef316e7b0d5b0f`：贸易站已有1980石，商人实际从公共仓库背出20木返站。玩家此时用1石换7主食，旧逻辑只看到站内1980−1+7=1986，没有考虑20木；木抵达后站内变2006，超过2000共享容量，生成的存档被载入校验拒绝。

这属于已有容量边界问题，不是增加新的贸易系统或改价格。

## 修复口径

- 只有已经从仓库背出、正在送往本贸易站的实际货批占位，空手计划不占。夜间挂起的同一批仍占位；同一任务同时出现在当前/挂起引用时只计一次。不同站各自计量。
- 实际领取时用「容量−站内现货−其他在途货」限制数量。玩家先交易时，后来的工人只取余下可放的数量；工人先取货时，交易必须给这批货保留仓位。只读报价与真正成交复核使用相同口径。
- 在途货不能作为付款库存。支付会释放站内空间，因此净占位减少/不增加的合法交易仍可进行；牲畜和永久种子仍不占站内仓容。
- 入站再次核验实际空位。若异常状态下只放得下一部分，就只接收这部分，剩余实际货物受保护地退公共仓，不靠丢货恢复容量。
- 备货被中断或读档时，现有任务重启合同不保留原路径/交货任务；在途占位随该任务取消，已经领取的实际货物受保护退公共仓，满仓保留余量。占位根据活跃任务推导，不另存一个容易重复累计的计数。
- 面板显示「已入站＋在途占位／容量、可用空位」，容量不足的购买说明明确包含在途占位；刷新保留当前输入和焦点。

旧合法存档无需迁移，本片不放宽非法超容量档的载入校验、不擅自删库存修复已坏数据。原贸易站库存撤回的其他通用运输规则没有整体重构，不将这次保证扩写为所有历史满仓货物都无损。
