# 施工无法完成：可达工地入口

0.3.11 施工入口修复。复现基线为 0.3.9（`498c755`），发布候选已整合 0.3.10（`e876994`）。不修改建筑成本、施工工时、经济参数、工作岗位数、昼夜规则或存档格式。

## 确定复现

原生地图 `newGame(11)`，正常付费依次放置四座木屋：

- `(33,29)`、`(35,29)`、`(37,29)`、`(39,29)`
- 共扣除 64 木、32 石，剩余 16 木、16 石
- 10 名成人由正常调度分配，不迁移市民、不赠送资源、不立即建成、不改地形
- 以 0.25 游戏小时步长推进 12 天，基线四个工地仍是 `site`、0%、90 剩余工时；此时占地树已清完（第二座原有 2 棵树）

工地南侧与天然水面形成了不可达口袋。施工只选直线最近的可站立边缘，寻路失败后反复选同一个点。北侧 `(33,28)` 等入口真实可达，却未被尝试。因此这是施工入口选择错误，不是建材未付、没有工人或 `finishBuilding` 本身失效。

该布局是合法但刻意构造的重现。没有用户存档，不能据此断言它是用户当局的唯一原因或估计普遍发生率。

## 最小修复

`workSpot` 增加可选的可达性检查。纯施工请求使用此检查，按原来的距离和稳定并列顺序尝试边缘点；第一个可达点用于正常行走和施工。

- 不更改其他调用者的入口选择、生产或回家逻辑
- 所有边缘都不可达时继续等待，不从建筑内部退到远处“隔墙施工”
- 下次派工重新按当前地形判断，拆除或通路恢复后可以继续
- 清场树认领、砍伐、搬运、跨夜挂起及已完成工时保持原机制

## 验证

`node tests/building-completion.js` 共 8 个用例：

1. 原生 seed 11 四屋通过北侧正常完成
2. 保存、读取施工队列后完成，无追加扣材
3. 取消一个未开工工地全额退款，其余工地正常完成
4. 原生 seed 1 有树占地的清场、送仓、夜间挂起和施工全链路
5. 合成几何：完全包围时不能隔墙建造，重新开通入口并铺原有土路后恢复
6. 合成几何：最近的不可达边缘让位于较远可达入口
7. 合成几何：夜间续接与调岗不丢失建筑已完成的工时
8. 原生完成后，普通选中详情由“建造中 / 取消工地”更新为住宅状态和“拆除”

前两个真实地图用例在未修版本中失败，修复后全部通过。四屋分别在第 5 天 07:00、第 5 天 21:30、第 7 天 11:15、第 10 天 10:00 完成；12 天内零死亡。合成几何测试单独标注，不当作自然开局证据。

另外，对固定 seed 1、2、3、73 的正常两年策略做前后轨迹对照，除源码哈希外所有记录完全一致（建造进展、末态、资源、死亡与日摘要）。完整仓库回归包括 README 列出的 Node/Python 检查；`bench`、`opening` 等诊断输出不等于全指标有断言。额外的默认 30 年 `long_economy` 报告在 seed 41 仍列出 3 项未达标：下一代生育、工具不断供、无可预防死亡；其退出码 0 不能当作长期经济全通过，本次不扩范围调整它。

离线原生 Canvas 可加载实际游戏渲染器与素材，观察工地到建成木屋的变化；DOM 检查验证详情文本。这些不是浏览器、手机或真人操作验收。当前浏览器连接限制未通过替代路径绕过。

## 暂未改动的独立边界

- 详情按钮持有键盘焦点时，非伐木屋面板的刷新保护在独立 DOM fixture 中确认会保留旧显示，失焦后恢复，需独立处理；普通无焦点的完成状态更新已验证。
- 回家策略按直线距离判断露营，复杂绕行可能耗尽工作日；本修复不调整作息、道路速度或通勤规则。
- 真正四周都不可达的工地仍不能施工，玩家需要保留通路；本修复只让现有可达入口不再被忽略。
