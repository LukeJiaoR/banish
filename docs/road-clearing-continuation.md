# 道路清树后接续施工

## 操作与边界

- 桌面拖到预览终点松手，或手机两点预览后确认，同时建立原有 roadwork 与普通清树标记。不先清空树、不瞬间铺路、不预扣材料。
- 每条新订单的待铺格全部实际清树后，原调度自动分配建筑工，沿原石材实运与逐格施工继续，无需再次点击。等待清树时工程不招工、不领石，单成人也能先砍树/送木再铺路。
- 确认覆盖路线中已成路上的树也会被标记，复用路面不重复收费。已成路格不归新工程占有，因此其清树仍是独立命令，不阻止新订单开工。
- 树木工时、木材产量/实运、工具消耗、石材价格、铺路工时、资源守恒、死亡和果园成熟年限均不变。水、山、建筑和矿石仍阻止提交；不清矿。
- 预览与确认之间树木或障碍改变仍拒绝旧意图，不静默换路。标记上限300，失败不建立部分订单。

## 暂停、取消、撤标记

清树沿用全村共享的普通砍伐标记，不创建第二套任务所有权。暂停或取消铺路只影响铺路；已确认的清树标记继续存在，避免误撤用户原先或其他任务共用的指令。预览、工程详情与取消结果都明确说明。

若也要停砍，可用砍伐工具的撤销清树标记按钮，范围是全图同类标记。未砍树仍在；已产生木材继续实际送仓。工程不会自动重建被撤销的清树标记，详情提示重新标记剩余树木或取消工程。重新标记后可继续，暂停工程则须先恢复。

取消施工保持既有规则：保留成路，现场未用石材返还，在途材料实际退仓，已投入未完路基计显式损失，不重复退款。

## 存档

复用现有 roadWork/marked 数据，不加新格式或新物资账。带树的未开工道路允许保存；仍验证地形、建筑冲突与独占索引。只要订单占有格还有树，整单必须没有施工进度、已用石材、完工格、现场料或待送入材料。验证先在候选世界完成，失败不改变当前村庄。已撤销标记可合法保存，加载不重建它们。旧程序可能拒绝带树订单，不能用旧版本继续此类新档。

## 原版依据与适配

重新核查 [Shining Rock 官方 Toolkit 1.0.7 Build 170910](https://shiningrocksoftware.com/game/mods/) 的 resource/Game/Help/Buildings.rsc：道路支持左键拖放；放置后的工程经过清场、收料与建筑工施工，缺料时等待，材料可用后继续。只读取资源文本，未运行 Toolkit 程序。

本片借鉴“放置一次后接续清场和施工”的总体流程。整条订单清树后再开工、最多2建筑工、每格1基础小时、共享砍伐标记与暂停/取消不撤标记，是本作的最小兼容实现；不声称原版暂停规则或矿石处理已完全复刻。
