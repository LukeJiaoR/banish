# 道路通行时间寻路（0.3.22）

## 本片范围

给定起点和目的地，按预计通行时间选路，而不是偏向较短格数。普通地面速度1.6、道路2.6格/游戏小时与实际移动共用；斜向长度使用√2。携货0.9、冬季0.75仍由移动系统照旧计算，恒定倍率不改变同一趟路线的优劣次序。

从格中心到相邻中心，前半段处在起点地面，后半段处在终点地面，因此边耗时为“长度的一半×两端速度倒数之和”。旧版本只算终点路面，并用未按最快速度缩放的启发项，会错过绕行但更快的道路。

这只是中心节点路径的连续时间估算。现有移动仍在每个模拟步开始取一次速度；较大步长、分数位置的首段、途中换季会造成误差。本片不声称有限步长下全程耗时精确相等，也不改所有移动积分。

## 路线与实走证据

固定起点(3,12)、终点(23,12)，道路经y=9绕行：旧路线20格，实际约12.260小时；新路线约24.828格，实际约9.550小时，少约22.1%。独立Dijkstra得到同一最小预计时间9.549395小时。测试实际调用stepCitizen，不用直接设置到达坐标替代走路。

另覆盖混合路面、斜向、携货、冬季、60张固定随机障碍地图与独立Dijkstra对照。240张稀疏道路编辑状态检查242,880条有向相邻边的一致性，并验证目标在道路框内/外、拆路与远处新增道路。

## 较紧的安全下界

无道路的已知地图使用野地速度的八向距离下界；未知地图保守使用最快速度。

有路地图记录包住所有道路单元的矩形，向外扩半格以匹配round位置取地面。设八向直达距离为d，目标到此框的最短八向距离为t：

- 全程不用路，实际时间至少d/野地速度。
- 使用道路，总长至少d；离开最后一处道路后，必经野地末段至少t。时间至少d/最快速度+t×(1/野地速度−1/最快速度)。
- 取两者较小值，不强迫任何路线先去道路，也不高估框外的短距离纯野地路线。

道路计数和包围框经正常铺路、确认铺路、拆路、世界生成及读档入口维护。新增道路扩框；拆路可以留较大的框，结果只会更保守。没有每帧全图扫描，也没有缓存每一对起终点的路径。框/计数不属于存档权威数据，读档从实际道路重建。

## 动态障碍

市民行走时检查下一段及斜向侧格，避免新建筑出现在旧路线后仍穿过去。检查使用实际分数位置所在的round格；不能用floor/ceil把合法首段误认为跨了旁列。此错误在本地首轮导致重复等待与城镇失败，已有最小短模拟回归并保留失败计数。

确需改道时才寻路，无法到达则至少隔两游戏小时重试，不每帧重寻。任务剩余工时和背货不凭空完成。旧终点被占时，住宅/仓库重新找真实入口，实体建筑工作重新找该建筑的工作点。森林采集/狩猎、砍树和农田属于物理地格目标，不能改成小屋门口假工作。实体工地覆盖这些目标时立即释放失效认领，让真实建工接手清场，保留已获得的背货；sendTo和夜间resume共用此终点限制。不能把附近任意空地视为入屋或交货。不能到达的矿物交货回到既有带矿等待状态，保货且不冒充可用劳力。

另修正配套调度合同：全森林目标被实体工地覆盖时，采集/狩猎的任务、岗位可生产判断与紧急粮工统计必须一致。无目标岗位释放闲人，工地可真实清场；不恢复隔着建筑假采集。保留原总树密度/产量门槛，只追加“至少一处合法目标”，部分树仍可采时继续工作。一次调度内按建筑记住判断，避免逐人重复扫描。

2成人、6树全被新仓库覆盖的红绿：旧候选4日0清树且2人虚占粮岗；修后10粮前置条件4日清4树、仍在搬运，32粮（仍处粮紧阈值内）8日清完6树并推进施工。新增木材严格等于实际移除树数×单株产量，没有凭空补粮/仓容；猎人全覆盖与只剩1合法目标也有回归。最终40局与此修前逐字段相同（除源码hash），6个路径计数案例的A*次数、扩展、单步突发也完全相同，仅合法格检查增加约0.07%–0.19%。

冻结运行源码的7批AB/BA交替，每批每版本720次固定查询，均0寻路失败。近/远目标、无路/合法空地道路布局都有包含。每批分位数的范围如下：

|版本|p50|p95|p99|
|---|---:|---:|---:|
|0.3.21基线|0.040–0.042ms|0.831–0.922ms|3.260–3.383ms|
|本候选|0.183–0.192ms|2.169–2.271ms|6.617–6.992ms|

正确寻路仍比旧的错误高估启发更贵，不能称CPU减少。初版全图最快速度下界的p95为5.83–7.54ms；增加必须离开道路的野地末段下界后长尾明显缩短。两个轮次不是同一时刻，降幅不作为严格设备性能保证。[完整固定queries与批次数据](travel-time-benchmark.json)。

## 尚未涵盖

仓库与多个工作入口之间的选择仍采用现有优先顺序，本片不承诺总是挑全局最快的仓库；这是下一独立修复。已在途且仍可通行的路线不会仅因新增道路自动重新规划。道路绘制/采集交互是另一项改动。

所有性能数据来自同进程交替运行的dot VM测试，不能代替真实手机帧率、电量或触控验收。脚本生存也不能代替真人体验。
