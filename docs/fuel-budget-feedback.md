# 0.3.8 燃料目标与取暖预算反馈

基线：`742da7a412f5b915f0a5f04c4c47710f55b5eb8b`（0.3.7）。

## 已复现的问题

四栋已入住木屋整冬需要约120柴火，全镇库存100，某伐木屋目标100时，该屋已停止接新批次。旧面板只显示上限，建筑说明却称“柴火够用时自动停工”。资源栏悬停虽显示120需求，调节目标时没有同屏上下文，容易把生产启停线当成取暖保证。

## 本次改动

- 伐木屋调节按钮旁同时显示本屋目标、全镇柴火/原木库存和当前已入住住房取暖估算；HUD、生存提示和面板使用同一只读计算源。
- 整冬预算按当前已入住的完工住房计算。冬季另显示此后尚未扣除的需求与次数，不把本冬已扣除的柴火再次计入缺口；入住变化仍会改变预算。
- 目标只约束本屋接新批次，不是储备承诺。降低目标不会预留建设木材，已接批次仍可能耗木，其他伐木屋按各自目标工作；户外受冻也不由库存预算保证。
- 打开面板后，库存、住房需求、状态与工人信息继续刷新，同时保持燃料按钮的键盘焦点。切换选中实体时使用新实体的信息和回调。

本次不改变生产、配工、默认目标、取暖消耗、造价或人口规则。

## 操作对照与保留的风险

对基线进行固定种子5、21、40、41、49、54、55的正常操作对照。原策略在49/54/55的第45日各冻死一名无房儿童，但首年均没有饥饿或冷屋日，年末仍有98柴火。这三例不能归因于柴火耗尽。

将前三屋的脚本下单门槛从22木改为真实造价16木，或在前三屋下单前且入冬前暂设燃料目标50，七个种子首年都能零死亡。前者没有修改真实造价，后者也有储备取舍：54/55首年只剩38柴。

这些是现有玩家操作可行性的证据，不是引擎修复收益或通用攻略。五年追踪中，16木策略的55在第199日饥荒灭村；临时50目标策略的54/55在第203/202日饥荒灭村，5出现22饥饿人日。更早住房改变人口和后续决策轨迹，尚未认定唯一原因。未替换正式验收策略或删掉失败。

seed49第33日有18木、0石、104柴和约14.68天粮食，取消4个树标记（中止2项执行任务）后标记附近两处可达石矿，第三屋从原第56日提前到第37日，首冬死亡1→0；即时库存没有增加。54/55石头足够，这个条件性操作不触发，不能当作通用救援。一直把燃料目标设0的七个首冬则都耗尽柴火、各16冷屋日，首冬尚未死亡，代价如实保留。
