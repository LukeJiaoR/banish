日期：2026-10-22。审计基线 main `fd86c04e2ef39b57d64d7a8ebe20e8ea82f56d37`；#155 Draft `e06f4c470e62437acc0361b96f9262a85cd81240`。本目录仅研究文档、资产原件导出与排版参考图，未修改游戏运行代码或现用素材；新美术方案尚未实施。

## 结论

- 整套新美术**尚未完成**。主线已有建筑、普通林树、地表、水面、岸线与人物素材/绘制，但大部分仍沿用旧资源。#155 的船候选不含 assets/ 新文件，不能算建筑、树林、河岸整套交付。
- 可保留的历史基准有确切来源：最早入库木屋、仓库、三阶段普通/雪树源自 `04620b586bf5fd293cf2f6d1d605a6e82e8df860`（2026-10-06）。当前木屋/树保留共同可见像素；仓库经过内容编辑。最早 Git 版本与用户心中“最好的一版”是否完全相同，不能仅凭提交日期断言。
- 需要先固化**投影、脚点、比例和状态接线**，再按有限样式批量制作。图像更精细、建筑更高或配色不同，不自动构成透视错误。
- 有具体透视复核候选：教堂长右侧石基手工端点约 22.2°，较引擎 26.565° 更平；镇厅约 26.9°/26.4°、贸易站约 25.8°/25.3° 接近基准。手工点位约 ±3 源像素，见带线原图，不能当精密几何拟合。教堂左侧有阶梯和凸出门廊，不应当作单一矩形边。
- 人物男女/年龄已有真实字段，但画面只接通用成人/儿童动作；稳定脸型、职业造型、老人造型未成系统。林树只有阶段与雪态，算出的 variant 未参与选图，多形态并未落地。果园苹果/梨是另一套已接状态。

## 2. 引擎投影与图像契约

当前使用 Canvas2D。`js/render.js:54`：T2S(x,y)=((x-y)*32,(x+y)*16)。世界两轴为 (32,16)、(-32,16)，地面格 64×32，水平夹角 ±26.565°，属于 2:1 二等角投影，不是屏幕轴各 30° 的严格等轴测。

`sprDraw`（225–250）：图像下边中心锚定 `(cx,by)`；给定宽/高后按源图比例缩放，没有透视校正。图内透明留白也计入尺寸。人物水平镜像会翻转画中照明，需在未来统一光照验收中记录。

标准建筑（850、913–918）：占地四角由 T2S 计算；宽=(w+h)×32×BUILD_SPR_W；锚点取前角 B=T2S(x+w,y+h)。矩形占地的 B.x 与占地包围框中心不必相同，不能用图片“看起来偏心”直接判透视错。

BUILD_SPR_W 在317起按类型指定，如 house1.16、storage1.03、boarding1.04、tradingpost0.875、chapel1.08、townhall7/6。底脚修正：贸易站/市场 +1.5px，矿坑 +2，水井 +1，教堂 +6；dock 特殊 renderer 用 +6。屋顶高、宽度倍率、alpha 留白、地基偏移应分别记录，不以拉伸图像混修。

`sprites.js:16–34`：成人高17px、儿童12.5px；普通树幼苗/幼树/成熟高16/26/38px；果树宽52px。人物与门应在同一原生缩放截图测可通行门口高度，而非拿源文件512px与280px直接比较。

## 3. 已有状态、缺口与系统化方案

详细逐项在 [state-matrix.csv](state-matrix.csv)。以下“建议”均未实现。

### 房屋与工作场所
- 房屋事实来自 families.houseId/members、citizen.familyId/dead，区分 vacant / home / away；有家庭不等于人在家。现在是同底图＋标识、窗光、烟。冬季取暖还要求实际本日燃料消耗，不能以烟囱底图颜色推定取暖。
- blacksmith/woodcutter/tailor/tavern 已按真实任务判定 process / fetching / returning / hauling / unstaffed / paused / blocked / hosting / idle；仅分配工人或累计 produced 不能证明正在生产。其他行业尚需各自任务接线。
- 建议每建筑保留少量结构底图，状态用门窗、晾晒、工具、工作台、实际人物和烟效模块表现。空置/住户外出/在家不要各画一整张重复建筑；只有结构真的变化时才增加底图。停工应表现工具收起/动效停下，不能凭 worker 数持续冒“生产烟”。

### 人物与头像
- 已有稳定 id、sex、age、adult、name、job(建筑ID)、task/state/walkKind/carry 等，存档保留身份；职业 UI 从建筑类型推导。
- 当前画面只是共用成人/儿童 walk/idle/carry 与两类 work 姿势，通用 citizen 图标；未见稳定 portraitId 或职业/老人/男女完整选图。
- 建议稳定身份映射到脸型/发型/色组，年龄决定身体阶段，职业只加衣帽/工具与动作；职业变动不重抽脸，存读档/换季不能换身份。首批4–6个稳定身份样本，覆盖男女、儿童/成人/老人展示；不做性别×年龄×职业×动作×季节全组合整张图。新增身份规则需独立存档/确定性设计审查，不能混入纯素材替换。

### 树木
- 野生树存 i/x/y/b，阶段由出生天推导；当前仅三阶段×普通/雪态。seed+x/y 缩放已有0.94–1.06，variant算出但未用于换图，不能把缩放宣传为多种树型。
- 果园独立保存 type/planted/age/fruit/season/cycle；已按苹果/梨、有果/无果选图，legacy generic 复用苹果。美术不能生成未成熟果实或使霜损果再出现。
- 建议树种 → 稳定 silhouetteVariant → 生长阶段 → 季节覆盖；同树跨阶段保持形态家族。先两种轮廓/树种的小样，不把每棵树独立随机抽图。柳/竹若只是环境装饰先明示；若成可砍经济树种，需要另审数据模型，不借美术修改产量。

## 5. 先定基准，再做一个完整小场景

### 有界下一切片（建议，尚未执行）
固定32×32参考场景，保留好木屋和普通树作为并排对照；新做一套投影统一的白墙灰瓦小院＋草顶仓＋开放木棚工位，配一个短河岸段（石埠/土岸/岸草三模块）、一小块院面、两种树冠各两轮廓。配置少量稳定人物身份与两种职业附件，展示空屋/外出/在家、真实加工/缺料/暂停、果树无果/有果。先覆盖一个完整视野，再决定扩充类型；不先铺满所有建筑，也不新增经济树种规则。

### 验收顺序
1. **投影底稿**：固定2:1地基四角、垂直轴、光向、门高、人高与前脚点。每个样式先做无装饰结构，屋顶坡线单独处理；用第一批保留图作材质质量旁证。
2. **一建筑一签名**：保存 source尺寸、地基四角、foot anchor、占地w/h、显示倍率、门口点、遮挡轮廓、光向。先解决 chapel 候选，不对所有后图批量拉伸。
3. **原生比例对照**：同镜头0.75×/1×/2×展示，附无标记图＋2:1线图；测人物/门和树/屋，验地基落地与矩形占地。数值容差由基准小样批准后固定，不以本次人工粗点当生产门槛。
4. **真实状态**：用已存在的事实驱动住家/工作状态；暂停不凭空生产；身份在存读档/职业变化后稳定；果实遵守成熟和霜损状态。
5. **遮挡/边缘**：建筑前后人物、树后屋、河岸与水层、泊位/桥下船，透明边缘与昼夜/雪覆盖。不能因投影线通过就宣布遮挡通过。
6. **实际浏览器**：离线 PNG 只能证明该画面，当前尚无整套 A 实机通过证据。浏览器仍需在允许环境中完成交互、缩放及移动性能验收；验收需在获准且可用的浏览器环境中完成。
