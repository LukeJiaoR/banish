## 部署到服务器（收集试玩反馈）

零依赖、无需数据库，一个 Python 标准库脚本搞定静态托管 + 反馈落盘：

```bash
# 把 index.html / style.css / styles/ / js/ / assets/ / server.py 上传到服务器任意目录
python3 server.py 8613                    # 绑定 0.0.0.0，浏览器访问 http://服务器IP:8613
nohup python3 server.py 8613 > server.log 2>&1 &   # 或用 systemd 常驻
```

**反馈入口**：游戏右上角 📮。玩家**无需注册**，一句话反馈 + 可选昵称，勾选后自动附带当前存档快照（仅游戏数据），提交后即可在服务器上查看：

- 反馈存储：`feedback/feedback-YYYYMM.jsonl`，每行一个 JSON（正文、昵称、**游戏版本号**、进度摘要、**最近 60 天每日摘要曲线**、**最近 30 次建造/拆除记录**、存档快照、脚本错误、匿名玩家 ID、IP 盐值哈希）。

**反馈复盘与分析**（可复盘 · 可追踪 · 可分析）：

```bash
python3 tools/fb_stats.py                    # 聚合报告：版本分布/分类/闭环率/进度直方图/死因合计/饥荒深度/关键词
python3 tools/fb_extract.py --id p-xxxx      # 按玩家抽快照 → feedback/replays/*.json
# 可选 --server 指定反馈服务地址，--token 仅在本机运行时安全提供
# 可输出受鉴权保护的复盘链接；不要把令牌值或含令牌的链接提交到仓库
```

- `fb_extract.py` 导出的 json 就是标准存档：游戏内「📂 存档管理 → ⬆️ 导入存档文件」即可回到该玩家反馈时的已保存局面（含 60 天资源曲线定位问题发生的时点）；`--server/--token` 打印的链接打开游戏即自动载入。工具磨损累计值随存档恢复；旧档缺少该字段时从 0 开始。当前不保存随机数流位置、正在执行/挂起的任务和寻路，读档会重新调度，因此是状态快照恢复，**不是确定性逐步复盘**。
- 反馈表单带可选分类（bug/数值/卡关/建议）；每条反馈有稳定 id，处理完在 `feedback/FIXED.md`（格式见 `tools/FIXED.md`）登记一行，报告即统计闭环率并标注待处理项。
- 数值补丁发布时递增 `js/core.js` 的 `G.VERSION`，反馈自动归因到版本。
- 在线查看：反馈接口仅在管理员安全配置 `FEEDBACK_TOKEN` 后开放，并要求鉴权；未配置时接口关闭，管理员可在服务器本地查看反馈文件。本文不提供令牌值或含令牌的访问链接。凭证只在运行环境安全设置，不写入文档、命令历史或仓库。
- 防滥用：每 IP 每 10 分钟最多 6 条；单条 ≤1.5MB；月文件超 50MB 拒收；目录列表禁用。静态服务仅开放游戏首页、样式、脚本及 assets；反馈目录（包括盐值）、存档目录和服务器源码不通过静态 GET/HEAD 暴露。
- 公网试玩请按下方 HTTPS 反代配置；必须保留浏览器请求的 Host（包括非默认端口），否则存档接口的同源校验会拒绝写入/删除。

### 5–10 人各自试玩的部署说明

游戏模拟与渲染在每位玩家的浏览器运行；服务器提供页面、素材、匿名浏览器隔离的存档和反馈，并不运行共享村庄。支持多人同时各自玩，尚无账号登录、跨设备自动同步或同村实时联机。

Python 标准库 `http.server` [不推荐直接作为生产服务器](https://docs.python.org/3/library/http.server.html)。少量朋友试玩也应通过已配置 TLS 的 nginx 等反代访问；下例仅为配置说明，不会自动部署或修改主机设置：

```bash
# 后端仅监听本机；仅信任同机 nginx 的实际连接来源
BIND_HOST=127.0.0.1 TRUSTED_PROXY_IPS=127.0.0.1 COOKIE_SECURE=1 python3 server.py 8613
```

在已有 HTTPS server 块中使用：

```nginx
location / {
    client_max_body_size 8m;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For "";
    proxy_pass http://127.0.0.1:8613;
}
```

- `TRUSTED_PROXY_IPS` 默认空，所有转发头均不受信任；可配置逗号分隔的**精确 IP**，不接受主机名或 CIDR。仅当 TCP 对端匹配时才使用一个合法的 `X-Real-IP`，缺失、重复或非法值均回退到 TCP 对端。始终忽略 `X-Forwarded-For`。
- nginx 必须用 `$remote_addr` **覆盖** `X-Real-IP`，不能原样转发客户端提交的值。不要把任意用户地址列为可信代理；若使用其他拓扑或上游 CDN，应单独核实可信边界，不能照抄成信任整个网络。
- 保留原限流：存档每真实来源 IP 每 10 分钟最多 90 次，反馈最多 6 次。不同代理后玩家不再被误算为同一个 nginx IP；共用一个公网出口的玩家仍共用该 IP 的配额。90 秒定时自动档每位玩家约 7 次/10 分钟，季节切换和离开页面会额外保存。
- 试玩配置估算：5 人可从 1 vCPU / 1 GB 起步；10 人更建议 2 vCPU / 2 GB、20 GB SSD 留出系统及备份空间。当前静态资源约 13.5 MB，首次集中打开或刷新时主要看出口带宽，建议 20–50 Mbps。当前 `no-store` 会让刷新重新下载；这只是资源和请求模型估算，**没有压测得出的承载保证**。
- 单次存档请求上限 8,000,000 字节；自动档同名覆盖，命名存档与备份会累计。`SAVES_DIR`、`FEEDBACK_DIR` 推荐置于站点根目录外并定期备份。不要静态公开整个仓库、存档或反馈目录。

本机轻量验证：`python3 tests/server_deployment.py` 覆盖 CSS GET/HEAD、可信/伪造代理头、实际限流，以及 10 个独立浏览器会话并行写入同名存档。使用合成数据，不代表真实玩家压力测试。

**资源目标**：顶栏可分别设置六种资源的全镇自动生产目标，达标停接新任务，消耗至显示的恢复线再开。0关闭新生产；“继承原规则”恢复原来的启停方式。新局和旧档默认均未设置。柴火/工具仍保留每屋旧目标，实际取全镇与本屋较低值。已接批次、手动采运和工地清场继续；已开始播种的农田按整田完成本季。目标不等于硬仓容，也不保证生存。语义和实测限制见 [资源生产目标](docs/resource-production-goals.md)。

💾 保存 / 📂 读取 = localStorage 手动存档；🌱 新游戏随机地图。
**存档管理（📂）**：面板中可查看、载入、删除「手动档」与「自动档」（含一键**清空全部存档**，带确认，不影响当前对局），显示存档时间和游戏内进度。
**自动存档**：每个季节更替、每 90 秒、切走标签页、刷新或关闭页面时自动写入「自动档」；下次打开自动恢复（结算后死档不恢复；🌱 重开会清除旧自动存档）。
**服务器存档**：用 `python3 server.py` 启动时，存档面板出现「🖥 服务器存档」区。首次探测由服务器签发随机匿名身份 Cookie（HttpOnly、SameSite=Strict，保留一年）；服务端按该 Cookie 隔离列表、读取、写入及删除，前端玩家 ID / owner 参数不能指定其他玩家的目录。自动档每 90 秒镜像到各浏览器独立的 `autosave.json`，同名不会互相覆盖。可输入名称另存、载入或删除。接口保留每 IP 限频、8MB 上限、名称校验与原子落盘；写入要求 `application/json`，拒绝跨源请求。Cookie 是浏览器的存档钥匙，请不要分享；同浏览器同站点的标签页仍共用存档。清除 Cookie、隐私窗口关闭或更换浏览器后不能找回该身份，跨设备请用下方 JSON 导出/导入。

部署到公网请通过 **HTTPS** 反代，并设置 `COOKIE_SECURE=1`，避免身份 Cookie 经明文网络泄露；本机 HTTP 开发默认不设置 Secure。不要让 nginx 等静态服务直接开放整个仓库及反馈/存档目录，也不要在同域托管不可信页面。数据默认仍在 `feedback/` 和 `saves/`，生产环境推荐用 `FEEDBACK_DIR` / `SAVES_DIR` 指向站点根目录外并备份。

**旧共享存档迁移**：升级不会删除或修改 `saves/*.json`，但无法可靠判定旧档所属玩家，因此不自动认领、不再通过 API 公布。管理员先离线备份，核实所属玩家后将对应 JSON 交还玩家，玩家在自己的浏览器导入后另存到服务器。新档位于 `saves/_sessions/<身份摘要>/`；不要随意移动该目录。反馈快照仍仅允许持有 `FEEDBACK_TOKEN` 的管理员读取。
**存档文件导出/导入**：存档面板底部「⬇️ 导出存档文件 / ⬆️ 导入存档文件」——把当前对局下载为 JSON 文件、或从文件恢复，任何静态服务器（含 dev-server.py、file:// 直开）都能用，是服务器不可用时的兜底。

## 系统概览

- **时间**：1 年 = 48 天（春夏秋冬各 12 天），1x 速度 1 天 ≈ 12 秒；速度档为暂停 / 1x / 2x / 5x（原版档位）。
- **市民**：A* 寻路（道路加速）、作息节律（22 点回家睡觉、6 点起床，深夜离家过远就地在工地露宿）、工作/搬运/进食/取暖状态机、家庭与生育、饥饿/受冻/衰老死亡（70 岁起）。冬季受冻按小时双侧结算（原版温暖模型）：户外累积、暖屋恢复、冷屋缓冻、露宿整夜挨冻；受冻值满 5 死（露宿整冬 4.8 勉强扛住，儿童 ×1.5 扛不住）。
- **住宅**：木屋 16木+8石（约 30 柴火/年）、石屋 24木+40石+10铁（20柴火/年，比木屋省三分之一）、宿舍 100木+45石（5 个无房家庭临时过冬，有空独栋自动搬出）；拆除建筑返还约一半材料。
- **矿藏**：地表岩石/铁矿用「采石采铁」工具标记、散工清除入库（各 10/格，约 6 工时）；新矿井铁/煤共用有限储量，新采石场有限4000石；详情显示剩余和预留。首次产矿后拆除永久留坑，旧档矿点仍无限并保留旧混采。
- **教育**：学堂开学后孩子 10 岁入学，满17岁且1344真实课时毕业（每所至多20人，每日最多6小时）；毕业工人干活更快、砍树每棵 3 原木、伐木屋 1 原木出 4 柴火。师生共同到校才计课时；教师离职/学堂拆除优先转校，无处可去时保留学籍。永久退学需二次确认。
- **林业**：护林小屋砍倒一棵即在原坑补种一棵（可持续轮伐，不砍光不停摆），面板可分别开关「砍伐 / 补种」（原版 Forester 的 Cut/Plant）；非冬季森林还会极缓慢地自播扩张（全图每年约 25-30 棵，规模造林仍靠补种）；伐木屋实物加工——工人到仓库/堆料场领取2原木并立即出库、携木回屋劈柴、再送柴火，挨着仓库建更快；伐木屋面板可调「燃料上限」（原版 Fuel Limit），柴火库存达到上限自动停工（默认 100，±50 可调；扩张后根据已入住住房的整冬需求提高）；新矿点所选产物满仓或储量耗尽时不接新批；仅旧混采矿井沿用石铁满仓回退。
- **狩猎**：工作圈内须有真实可达野鹿；猎人追踪、完成猎杀、实背肉皮入仓。同屋两人共享8日猎杀间隔，鹿在林边活动并持续补充，不按树数直接发肉。林地被清空会使鹿转往其他栖地，不会啃食作物或永久灭绝。
- **标记砍伐**：「砍伐」工具点击或拖拽沿线标记树木（原版 Cut Down Trees），无业散工前来砍倒入库；清场开田不再依赖护林小屋。
- **劳动力自动调度与手动上限**：建筑详情可设 0 至原最大人数，低于现有人数时先释放闲人，有限批次结清再释放；教师/医生/接待停用后立即停止服务。上限不是保证人数，缺粮救急也不会突破玩家上限；全镇概览区分占岗、收尾和无岗带货。工地可暂停/恢复，保留已完成工段及已付材料，未完成小工段重新开始。默认仍是工地 > 工作岗位；工地可从普通岗位抽人（教师除外）；有「砍伐/清石」标记时给散工保留 1–2 人，无业者不足时自动从闲余岗位（柴满伐木屋、当前矿种仓满或储量耗尽的矿井、非收获季农田、人手富余的非粮食岗）释放工人承接——标记清完后回流岗位（扩张期清石/砍伐不停摆）；粮食岗位按人口保底；春夏农田工人自动流转去伐木备柴，秋收自动回流抢收；关键岗位缺人时按优先级从「正闲着」的工人处回收，不会永久空转。
- **季节**：植被换色、冬季降雪、房屋窗户透光、炊烟；未收获的农田作物会被冻死。
- **失败/胜利**：全员死亡即结算；活下去、多生娃就是胜利。

## 0.3.3 经营提示与修复

- 先保连续食物收入，再建近仓的伐木屋与住房；第一冬优先让有孩子的家庭有屋过冬。不要一口气开很多工地。
- 采集屋周围的森林就是食物来源。标记砍伐尽量避开其范围，农田也不要把食物林整片清掉；远处资源有实际搬运成本，道路和就近仓库有意义。
- 保留采集单次基数 5、食物消耗、寒冷、工具磨损和建造成本。单变量 5/6/7 对照曾显示增产有帮助，但修复最后的派工中断后原基数已可通过主验收，因此未保留增产补丁。
- 柴火默认目标从 200 改为 100，避免开局把住房用木全劈成柴。建更多住房后，在伐木屋面板按需求调高；资源栏悬停显示库存容量、可供食物天数和整冬燃料需求。
- 工具尚有约一年用量时就提前告警；资源栏悬停可看约可用天数。近处石矿耗尽时要向外勘探并考虑铺路，不能等工具归零才筹建铁匠铺。
- 铁匠铺默认保有 30 件工具，达到目标自动停工，面板可 ±10 调整。目标是启停线，已开工的一批可能小幅超过；木/铁仍真实消耗，磨损仍持续，工具用尽仍减产。
- 新地图保证储物车能够落地，并在镇边补足至少三块可开采铁矿，解决“零铁却必须用铁建矿井”的工具循环死锁。没有赠送铁库存，仍要标记开采；旧存档地形不追加矿石，新存档保存地图版本与清矿记录。
- 物流修复：农田尾批及时送仓、所有交货经过容量检查、绕开不可达仓库/资源目标。调度修复：无活农田不抢工、跨夜清石保留进度、暂停农活保留认领、预留散工不阻断再平衡、低粮优先返工保食物。
- 本轮保留先前服务端隔离、安全静态托管和快照恢复修复。模拟与离线美术检查不等于真人试玩或浏览器交互验收。
